# 面向 MLP 的 Hessian-free TS 搜索：设计记录与接手路线

日期：2026-10-24。用途：统一研究问题、解释当前实现缺口，并给后续维护者明确的修复与验证顺序。

2026-10-25 施工进展：[HF-2/3 独立 E/F 定位原语](HF_EF_LOCATOR_2026-10-25.md)
已实现并完成解析台测试；尚未接入 D2、恢复或真实模型验证。以下保留 10-24 设计快照。

**结论：总体研究思路成立，当前实现还需要把 TS 局部定位贯彻成 Hessian-free。**
目标是在能量和力足以支持探索、而高阶导数难以可靠使用的 MLP 上寻找过渡态。完整路径是后续可恢复、可核验的结果；不要求先构造完整路径才能开始找 TS。方法能否比已有方法更稳、更省，需要实验回答。

本文记录用户已明确的方向，以及本轮源码复核得到的修复建议。**只交付设计与文档整理；未实施算法、状态格式、预算或判据修改，未启动新的分子计算。** 原有冻结协议、C1/C2 定义和历史结果保留。后文的新接口、阶段名与施工顺序均为建议，不能当作已经存在的功能。

## 1. 研究问题与方向来源

本轮用户连续澄清了三个重点：

- 「我整个算法都是 hessian free」：研究目标是用 E/F 完成搜索，不把可靠的 MLP Hessian 作为前提。
- 「就是为了解决这个问题」：高阶导数难以可靠使用是方法的出发点，而非要求搜索器先替模型解决的问题。
- 「现在这是找 TS……路径真的顺着摸下来就行」：TS 定位是核心交付，双侧下降和路径重建在其后。

因此，当前论文与实现的主线应表述为：

> 面向 MLP 的 Hessian-free 过渡态搜索：利用能量和力产生、夹住并精修 TS 候选，在不依赖可靠模型 Hessian 的条件下评估定位能力、稳定性与成本。

这是有条件的研究问题，不宣称所有 MLP 都没有可用 Hessian，也不宣称只要不用 Hessian 就会优于其他方法。能量、力或模型化学适用域本身失效时，Hessian-free 算法也不能恢复缺失的物理信息。

## 2. 算法边界与术语

| 对象 | 在本主线中的位置 | 可用的表述 |
| --- | --- | --- |
| 姿态、意图和受控探索 | 产生 TS 初猜及局部两侧信息 | 不要求已知产物、参考负模或完整反应路径 |
| E/F 局部 TS 精修 | 核心搜索算法 | 用完整无偏力、约束残差与局部分支信息判断数值收敛 |
| 搜索几何与方向 | 搜索的直接工件 | 已收敛驻点候选；其阶数与化学连接另行核验 |
| 两侧下降 | TS 之后的连接追踪 | 保存启动方向、位移尺度、下降记录与端点；下降不是完整 IRC 的同义词 |
| MLP Hessian／独立参考 | 搜索后的可选性质检验或评分 | 检验失败不能抹掉搜索几何，也不能被改写成检验通过 |
| 独立 QM | 化学结果核验 | 分别记录重优化位移、频率、连接与能量变化 |

本记录中 Hessian-free 指搜索更新不调用模型完整二阶导数，也不通过逐坐标力差分重建完整 Hessian 后求谱。由 E/F 历史产生的 BFGS 等近似可以使用；它不要求 MLP 提供准确 Hessian。

有限幅度的双侧 E/F 响应也可作为方向信息，但必须记录幅度及其分辨率。它可能对力差分噪声敏感，不能仅因没有显式矩阵就声称与曲率误差无关。

数学上的“一级鞍点”仍有阶数要求。小残余力、反力过零、两侧下降或抽样方向检查，单独都不能自动签发严格的一级鞍点认证。搜索收敛、数值性质核验、化学连接核验分开保存，避免把未决当成功，也避免把检验瓶颈误计为搜索失败。

### 2.1 与 NEB、IRC、Dimer 的关系

这些方法可作为任务与基线参照，不能统一归入“必须依赖完整 Hessian”的一类：

- 常规从 TS 启动的 ORCA IRC 用 Hessian 模式确定双向初始位移，之后沿梯度推进；所以困难应具体描述为 TS／负模初始化及其可靠性。[ORCA IRC 官方说明](https://orca-manual.mpi-muelheim.mpg.de/contents/structurereactivity/irc.html)
- CI-NEB 的攀爬更新反转切向真实力，不要求显式完整 Hessian，但需要路径图像提供可用切向。[ASE NEB 官方说明](https://docs.ase-lib.org/ase/neb.html)
- Dimer 本身是 Hessian-free 鞍点方法，利用位移结构的力获得方向信息，是直接相关的基线。[方法研究](https://arxiv.org/abs/1407.2817)、[ASE 实现](https://docs.ase-lib.org/ase/dimer.html)

本项目的差异应由具体的初猜生成、分支追踪、有限尺度响应、MLP 数值适配和实际成本来证明。“Hessian-free”本身不是对所有这些基线的独有优势。

## 4. 缺陷、证据与建议修法

### F1：完整 Hessian 参与 TS 搜索更新，优先修复

**代码位置：** [certify.py](../explore/src/explore/certify.py) 的 `certify`；[runner.py](../src/prrs/runner.py) 的 `follow_min_mode`、`curvature_spectrum`、`_mass_weighted_hessian`。

`certify` 调用 `follow_min_mode`；后者每隔若干步读取完整谱，选本征方向并用本征值缩放位移，收敛后还必须通过最终谱检查。`hessian_source="auto"` 可以回退到逐坐标差分，因此仅去掉 `get_hessian` 并不能保证搜索 Hessian-free。

本轮 CPU 反例：解析双阱的精确 TS 残余力为零；模拟完整谱不可用后，`follow_min_mode` 仍调用一次谱接口并返回 `None`、`gate_review_unusable_hessian`。这证明依赖发生在定位函数内部，而非仅在外部报告中。

**建议修法：** 新建独立 E/F 定位接口，先得到可持久化的搜索结果，再交给独立检验。旧精修器保留作基线／历史复现。不要通过关闭检查、把原 C2 改名或把 `minimum_check="none"` 的返回值当作认证来完成迁移。

### F2：离散最高点之后缺少 HF 定位步骤，优先修复

**代码位置：** [d2.py](../explore/src/explore/d2.py) 的 `_promotion_points`、`_certify_task`。

当前通常将离散峰点、或跳支前几何交给旧精修器。分支上的反力已保存，却没有用来将粗网格初猜收敛为无偏驻点；峰点也不要求完整力足够小。

**建议修法：** 先实现第 5 节的连续分支反力零点精修，明确记录“粗扫初猜 → E/F 收敛候选”的几何与成本。跳支情形保留双分支信息，不能把两个分支的反力直接夹成同一个根。

### F3：判读混入未收敛尾点，存在明确实现漏洞

**代码位置：** [probe.py](../explore/src/explore/probe.py) 的 `read_scan`。

`falls` 取所有后续能量的最小值，但前面的收敛检查只覆盖到峰后相邻点。CPU 构造 `E=[0, 1, 0.9998, -3]`、最后一点未收敛、`noise_eV=0.001`，仍触发脊；真正合格的峰后相邻下降只有 0.0002。

**建议修法：** 所有支持升降的点都必须来自同一段合格响应；未收敛／域拒绝记录保留，但不用于证明峰后下降。测试同时覆盖“后续有效下降”和“后续失败点伪造下降”。

### F4：同键图跳支没有连续性证据，属于判据覆盖局限

`read_scan` 只有键图变化且能量下降才报告 `jump`；同图构象突变可得到 `ridge_suspected`。CPU 构造相同键图、峰后横向几何突变 2 Å，仍发出脊触发。这说明筛选器没有连续性核验，不证明历史分子结果已经错误。

**建议修法：** 按实际几何、力和反力追踪分支。可使用对齐位移、局部切向变化、正反扫及步长缩小核对；`ΔE` 与反力积分的偏差只作诊断，不能单独证明换支。所用尺度需来自测量，不能凭空设统一硬阈值。几何不连续时先保留两侧，再做局部复扫。

### F5：要求峰高于整条扫描起点，会漏掉局部 TS 区域

`rises = E_peak - E_start > noise_eV`。CPU 构造 `E=[5, 0, 2, 0]`，中间峰有局部升降与反力变号，但返回无触发。L0 姿态可能高于后续局部鞍点，因此这条旧筛选语义不适合作为找 TS 的必要条件。

**建议修法：** 在合格、连续的局部区间识别上升—下降与反力符号；对初始姿态的能量上升上限继续作为成本／定义域约束单独记录。改变该语义须建立新规则版本，不追认旧批次。

### F6：原搜索方向没有传给局部精修

`certify` 接受 `direction`，但 `_certify_task` 没有传。旧精修器因而默认选最低非平凡模，可能转向软扭转或片段运动。

**建议修法：** 保存峰前／峰后几何、局部切向、坐标定义、原子映射和分支标识；局部 E/F 定位持续追踪方向并报告漂移。把方向传给旧精修器只能减少部分漂移，不能修掉 F1 的完整谱依赖。

### F7：准备与两侧下降仍可能隐藏 Hessian 必需调用

`qualify_conformers`、`release` 和 `descend_saddle` 会调用 `confirm_minimum`；当前 `certify` 还会在 `minimum_check != "hessian"` 时直接返回。因此只替换局部更新还不足以宣称端到端无 Hessian。

**建议修法：** 审计准备、搜索、端点追踪、独立检验四部分的实际调用。搜索可以接受明确标记为未严格认证的输入；E/F 松弛和有限扰动检查仅提供相应等级的稳定性证据。严格性质认证作为独立步骤保留，不能静默变成“通过”。TS 两侧的启动方向优先来自搜索本身，并核对位移尺度下的端点稳定性。

### F8：预算与报告仍围绕旧连接认证目标

当前 D2 严格先做全部 L1，再处理 L2、释放和认证；`_promote` 每项先释放后认证。已完成 b05 旧批次出现粗扫耗尽搜索额、释放为零，以及认证只覆盖少数升级项的情况。另有检验未决被折叠进整体 L4 未决，不能直接用于计算纯搜索成功率。

**建议修法：** 在新协议中为局部 TS 精修留出明确额度，按有界波次交替探索和精修，TS 后再追踪连接。分别保存搜索收敛、性质检验、连接与 QM 结果。预算分配／调度属于策略变化，须记录版本并与旧固定分相策略区分；失败、中断和重算继续计费。

## 5. 推荐的最小 E/F 定位内核

### 5.1 连续分支：约束松弛与反力零点

现有坐标是标量 `q(x)=Σ c_k r_k(x)`。令 `g=∇q`，`F` 为完整无偏力，且 `g != 0`：

```text
F_perp = F - (F·g)/(g·g) g
lambda = -(F·g)/(g·g)          # 当前 reaction_force
```

在约束分支 `x*(q)` 已充分横向松弛时，`lambda ≈ dE*/dq`。因此在分支光滑且坐标非奇异的条件下，`F_perp≈0` 与 `lambda≈0` 一起给出 `F≈0`。这提供只用 E/F 定位驻点的直接途径。

建议步骤：

1. 从合格、连续的峰附近保存两侧几何与反力；按实际 q 的增减解释符号。按 q 递增排序时，局部极大对应反力由正到负。
2. 在同一分支内使用有界二分或受保护的割线更新 q，保存括区与每次横向松弛结果。
3. 每次核对约束残差、横向力、完整力、有限值、定义域和预算；失败时保留最近有效括区。
4. 以实测力／反力分辨率及几何精度共同决定终止，不能要求噪声以下的精确零点。仅 q 区间很窄不等于驻点已收敛。
5. 保存收敛候选及搜索两侧信息，然后执行独立性质／连接检验。

这是有条件的推荐内核，并非一般 TS 完备性证明。如果横向分支确为严格局部极小、分支光滑且局部最大非退化，可得到对应的一阶鞍点结构；当前 BFGS 的小投影力并不自动证明这些条件。横向失稳、平坦区或分支终止要明确记未决。

### 5.2 跳支与滞回：保留双侧信息后再定位

两个局部极小分支并存，不意味着它们的反力属于一个连续函数。不能直接平均几何、跨分支插值求根或把能量突降解释为已穿过 TS。

首版先缩小扫描步长，分别延续两侧分支；若仍不能形成连续的定位区间，保存双侧几何并返回明确的分支未决结果。之后再比较有限幅度响应驱动的 E/F 局部鞍点更新；Dimer 可作基线。这个扩展不要求先计算全反应路径，但需要自己的收敛、方向漂移和尺度验证。

### 5.3 MLP 数值适配

- 同时测量 E、F、反力与转动协变残差；能量的 fp32 量化分辨率不能直接充当反力容差。
- 有限幅度响应不盲目取极小位移；验证幅度、步长与结果的稳定区间，同时限制扰动离开局部结构域。
- 旋转／平移对齐只用于移除整体刚体运动，不能消去真实的片段相对运动。
- 约束求解必须记录实际残差；求解器步数耗尽、`∇q` 退化及零距离等不能只靠小投影力判成功。
- 原有 fp32 Hessian 噪声实验给出的约 1.8 Å 差分步长不能直接上线；需另查单位、噪声定义和局部性。这项独立核验研究不作为 E/F 搜索开发的前置条件。
- 延续用户当前的精度方向，不把升格计算当作本算法成立的前提。改变算术精度和提高模型物理准确性分别评价。

## 6. 建议接口、结果与预算合同

以下是待施工的概念接口名，不是现有 API：

```text
refine_ts_ef(candidate_bracket, evaluator_ef, settings, ledger)
    -> search_result
trace_sides_ef(search_result, evaluator_ef, settings, ledger)
    -> connection_result
validate_ts(search_result, validation_protocol)
    -> property_validation / qm_validation
```

`search_result` 至少包含：候选 ID、输入来源／意图／括区、结构和原子映射、电子态、无偏 E/F、约束残差、横向残差、反力、方向／分支、停止原因、实际求值与墙钟，以及可续跑的历史。局部精修还应报告初猜到结果的位移与方向漂移。

结果维度分开：

| 维度 | 建议结果 | 边界 |
| --- | --- | --- |
| 搜索 | 收敛／预算截断／分支未决／数值失败／离开定义域 | 收敛仅表示按明示条件得到驻点候选 |
| 驻点性质 | 通过／不通过／未决／未执行 | 必须写明在哪张 PES、使用什么检查 |
| 连接 | 双侧端点与事件／同盆／失败／未决 | 保存启动方向和端点资格；不把下降轨迹等同完整 IRC |
| QM | 重优化、频率、连接、能量及失败 | 同时报告 QM 重优化前后位移，不能用远距离迁移后的成功替原定位背书 |

保留原 C1/C2 及其判据，新增搜索结果维度，不降低旧认证标准。MLP Hessian 与独立 QM 的结论也不互相覆盖。

预算至少能分别核对准备、探索、局部精修、连接和外部验证；不要求立即搭建五套账户，可先用阶段字段分账。主比较仍包括对应搜索策略全部实际 E/F 成本、失败与重算。外部统一评分成本和独立 QM 单列；若验证会反馈改变搜索或重试，它就是策略成本，不能免费隐藏。

## 8. 论文、未来方向与项目整体位置

### 8.1 首篇需要的证据

```python
import numpy as np
from ase import Atoms
from explore.probe import ScanPoint, read_scan
from prrs import runner
from prrs.calculators import double_well_factory
from prrs.config import SearchConfig
from prrs.reliability import GateRejected


def point(k, energy, rf, converged=True, shift=0.0):
    positions = np.array([[0., 0., 0.], [1.5 + 0.1*k, 0., 0.], [0., 2., shift]])
    return ScanPoint(
        0.1*k, 1.5 + 0.1*k, 1.5 + 0.1*k, energy, rf,
        0., converged, 0, [[0, 1]], positions, np.zeros((3, 3)),
    )


cases = {
    "same_graph_jump": [point(0, 0, 1), point(1, .6, 0), point(2, -.2, -1, shift=2)],
    "failed_tail": [point(0, 0, 1), point(1, 1, 0), point(2, .9998, -1),
                    point(3, -3, -1, converged=False)],
    "peak_below_start": [point(0, 5, -1), point(1, 0, 1),
                         point(2, 2, 0), point(3, 0, -1)],
}
for name, points in cases.items():
    print(name, read_scan(points, noise_eV=.001))

atoms = Atoms("C2", positions=[[0., 0., 0.], [1.8, 0., 0.]])
atoms.calc = double_well_factory()
print("exact_TS_fmax", np.linalg.norm(atoms.get_forces(), axis=1).max())
original = runner.curvature_spectrum
calls = []


def unavailable(candidate, *args, **kwargs):
    calls.append(1)
    raise GateRejected("review_unusable_hessian", "synthetic unavailable Hessian", candidate)


try:
    runner.curvature_spectrum = unavailable
    geometry, info = runner.follow_min_mode(
        atoms, double_well_factory, SearchConfig(closed_shell_only=False),
    )
    print("spectrum_calls", len(calls), "geometry_returned", geometry is not None,
          "reason", info.get("reason"))
finally:
    runner.curvature_spectrum = original
```
