## 1. 范围

做：
- D2 新规则版本 `D2-HF-v1`：升级项的 L4 由旧 `certify`（完整 Hessian 精修 + 下降）换成两个 E/F 任务：
  - **HS**（HF 搜索）：`continue_branches_ef` → `refine_ts_ef`；
  - **HC**（HF 连接）：`trace_sides_ef`，读取 HS 已结算的候选。
- 两者走现有 journal / ledger / 续跑机制。
- 报告里把搜索、连接、性质分开（§6 表）。

不做：
- 不改 L0–L3 与升级规则（F4/F5 的新判读是另外的规则版本）。
- 不改旧 D2-v1.1：`RULE_VERSION` 按 manifest 分流，旧 run 能照原样续跑和出报告。
- 不在 D2 内跑 Hessian：性质检验做成独立的离线脚本（§5）。
- 不做波次调度（F8 的策略变化）：首版沿用 M5 的严格分相，使与 b05 fp32 / v1.1 批次的对比只差 L4 方法这一个变量。波次调度另立 HF-4b。

## 2. 设计

### 2.1 括区（F2）

由 `_promotion_points` 旁新增的 `_hf_bracket(classified, points)` 给出：

| 升级类别 | 括区 |
| --- | --- |
| 脊 | (points[k−1], points[k+1])，与 b04 / b05 对照时一致 |
| 夹住的跳支 | (反应物侧点, L2 反扫得到的产物侧结构)，产物侧的 q 用 `intent.value` 现算 |
| 抽查 | (peak−1, peak+1)，与 M5-D1 的抽查定位一致 |

两端不信任保存的收敛标记：`continue_branches_ef` 会重新松弛两端。

### 2.2 任务与账户

| 任务 | 内容 | 账户 | 上限 |
| --- | --- | --- | --- |
| `HS|intent` | `continue_branches_ef(..., settings=EFSettings(σ, 中点 τ), branch_settings=BranchSettings(δ_geo))` | refine | `hs_cap` |
| `HC|intent` | 仅当 HS 为 `converged_candidate`：`branch_starts` + `trace_sides_ef` | refine | `hc_cap` |

- 账户：把 `certify` 改名为 `refine`（D2-HF-v1 下），HS 与 HC 共用。分账靠 ledger 的阶段字段（`ts_branches_ef` / `ts_search_ef` / `connect_ef`），对应 §6「可先用阶段字段分账」。
- 上限依据实测：HS 每项 215–861 forward（冷启动 ≤ 861，热启动 ≤ 284）；HC 每项 90–410。首版定 `hs_cap` 3000、`hc_cap` 3000，超出按 `budget_exhausted` 结算并保留已付。
- HS 与 HC 是两个独立任务、分别结算：HC 中途被杀，HS 的候选几何已在 journal 里，不会丢（HF-4 完成条件）。

### 2.3 新增设置（D2Settings，HF 模式必填，冻结进 manifest）

- `hf_reaction_force_sigma`、`hf_geometry_noise_A`：按体系实测（`hf_ef_rf_jitter.py`）；b05 = 0.0025 / 7e-3，b04 = 0.0042 / 6.2e-4。
- `hf_midpoint_transverse_fmax_eV_A` = 1e-3（DONE_LOG 10-25 J1 依据）。
- `hs_cap`、`hc_cap`。
- 没有默认值：缺了就拒绝 init，避免不同体系误用别的体系的噪声。

### 2.4 判重（替代旧 certify 第 5 步）

HC 结果为 `connected` 时，与已结算的 HF 连通项比较，三条同时满足判为 `hf_duplicate`：
- 化学对相同：两端 `chemical_key`，无序；
- 鞍点能量差 ≤ `basin_energy_eV`；
- 自同构下的 `symmetric_rmsd` ≤ `basin_rmsd_A`。

全部复用 `prrs.chemistry`，不涉及 Hessian。

### 2.5 报告（`_report`，HF 模式）

- 搜索：HS 状态分布、括区类别、forward 中位数。
- 连接：HC 状态分布、事件标签与键变化、去重后的连通事件数、每个事件首次命中时的累计支出。
- 性质：`not_run`，留给 §5 的离线脚本。
- 原有的 population / L1 / L2 / L3 / accounts / unreconciled 照旧。

## 3. 施工步骤

| 步 | 内容 | 完成条件 |
| --- | --- | --- |
| H1 | `d2.py`：规则版本分流、`_hf_bracket`、`_hs_task` / `_hc_task`、`refine` 账户、HF 设置校验、判重、报告。旧 v1.1 路径不动。 | 旧 `test_d2*` 全过（v1.1 行为不变） |
| H2 | 解析台（`d2_bench` 的 TwoSaddle）：HF 模式端到端，至少找到一个连通事件；外部计数器 == 各账本之和；`unreconciled` 为空。 | 新测试通过 |
| H3 | kill→resume：`d2_driver` 加 HF 模式，分别在 HS 中、HS 与 HC 之间、HC 中杀进程再续跑。已付成本只记一次（中断的按 cap 或账本记），HS 候选几何不丢，连通事件与不中断时一致。 | 三个杀点都通过，即 §7 的 HF-4 完成条件 |
| H4 | `benchmarks/explore_d2/run_b05_d2.py` 加 `--rule hf`；本机或 180/181 上做 b04 端到端冒烟一次（小参数）。 | 跑通，报告字段齐全 |
| H5 | b05 正式两块：同种子、同 L1 参数，与 `b05_fp32_s{A,B}`、`b05_v11_s{A,B}` 对比。refine 额度与旧 certify 同为 240k。PBS 脚本照模板写好；有空节点时交 qsub 命令。 | 跑完后报告：连通事件数（E2 / 取代 / 构象）、首个 E2 的成本、HS / HC 失败分类，与两批旧结果并列 |

H5 的时间依据：fp32 批 L1 约 2.0 h（4080S）；HS + HC 每项实测 ≈ 300–1300 forward，约 300 个升级项 × 约 800 ≈ 240k，与 refine 额度相当。fp32 认证在 4080S 上约 0.16 s/forward，E/F 松弛单次 forward 更便宜（未分开测），粗估 L4 ≤ 10 h；这一点在 H4 冒烟里实测单项耗时后再定 walltime。

## 4. 风险与已知限制

- HS / HC 首版逐项串行，没有接 `run_many` 合批（同旧 certify）；吞吐是后续执行层工作。
- 跳支判据在陡而连续的区段会误报终止（b04，DONE_LOG 10-25 J1）。只要另一侧找到变号，结果不受影响；双侧都误报时会被记为 `hysteresis`。
- σ / δ_geo 按体系只测了一点；b05 以外的体系先测再跑（§2.3 必填）。

## 5. 离线性质检验（不在 D2 内）

`benchmarks/explore_d2/hf_validate.py`：读 HF run 的 HS 候选，单独算完整 Hessian，得到阶数与虚频。结果另存，不改写 journal 和报告（§6「MLP Hessian 与独立 QM 的结论也不互相覆盖」）。在 H5 跑完后对连通事件执行。

## 未确认（Claude 推断）

- `hs_cap` / `hc_cap` 3000 只是按 5 个括区实测（≤ 861 / ≤ 410）留的余量，换体系可能不够。
- H5 的 L4 耗时 ≤ 10 h 是粗估，未测 E/F 松弛的单次 forward 耗时。
- 夹住的跳支括区（反应物侧 + L2 产物侧）在真实体系上是否形成同支括区，未验证；预期多数走 `hysteresis`。
