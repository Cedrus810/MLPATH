## 1. 要回答的问题

从同一份 L0（反应物输入与姿态库）出发、同一模型 / 精度 / 硬件、同一总求值预算 B*，D2 与 DB 各自能找到参照集 S 中的几个鞍点，首次命中各花多少（评估协议 R(b)、T_i）。第一阶段回答的是"给同样初猜谁定位得好"；本阶段把初猜的制作成本也算进去。

## 2. 两臂

### 2.1 D2（不重跑）

用已有运行：b04 `results/2026-11-09/b04_hf5_v14_sA`、b05 `results/2026-11-08/b05_hf_v14_sA`、N1 `results/2026-11-09/n1_hf5_v12_sA_n0020`。B* 取各运行的 ledger 总数（26 129 / 408 888 / 376 296 forward）。每个 HC 连通事件已记 `cumulative_spent`，与参照匹配后即得 D2 的 R(b) 与 T_i。

### 2.2 DB（新跑）

- **起点**：同一运行的 L0 姿态（`poses.jsonl`），原样坐标，不另做极小。
- **一次尝试**：从一个姿态出发，ASE Dimer 默认设定（`displacement_method='gauss'`、`gauss_std` 0.1 Å 的随机初始位移，`initial_eigenmode_method='gauss'` 的随机初始模式，`DimerControl` 其余默认），`MinModeTranslate` 到完整 fmax ≤ 0.01 eV/Å；单次上限 3 000 forward（与第一阶段、`hs_cap` 相同）。
- **调度**：姿态按冻结随机键轮转，第 k 轮对每个姿态用种子 (seed, 姿态, k) 做一次尝试，直到累计 forward 达到 B*；失败与额度截断照常计费。
- **不用的信息**：参照结构、产物、负模；D2 的扫描、脊或括区（第一阶段用了意图方向，本阶段不用）。

## 3. 共同的检验与计分（搜索之后，两臂相同，单独记账）

- 每个收敛的 DB 候选与每个 D2 HC 连通事件：`confirm_minimum` 阶数、参照匹配（对称 RMSD ≤ 0.15 Å 且 |ΔE| ≤ 0.05 eV），同 `hf6_local_summary.py`。
- 一阶且匹配参照的才计入 R(b)，以它被找到时的臂内累计 forward 为命中成本；同一参照的重复命中不再计收益。
- D2 的事件已经过 HC（E/F 两侧连接）；DB 的候选没有连接步骤。为可比，两臂计入 R 的鞍点都只按"一阶 + 匹配参照"计；连接另报：DB 命中的参照鞍点补做两侧下降（`descend_saddle`，检验端，不入搜索预算）。
- 报告：B* 网格（0、1/8、1/4、1/2、3/4、1）上的 R；每个参照的 T_i（未命中记右删失）；参照外一阶鞍点数；DB 的失败类别（额度截断 / 落到极小 / 高阶 / 数值失败）。

## 未确认（Claude 推断）

- 原样 L0 姿态多数是分离的复合物，Dimer 从那里出发、0.1 Å 随机位移，可能大部分尝试都收敛到复合物软模鞍点或用完额度（b09 10-09 的 PRRS 探针有类似现象）。这会是基线的结论，不在本轮调参。
- 第一阶段 Dimer 用 0.07 s / forward 是 3 进程共用一张卡时的均值；单进程会快一些。
- R(b) 只计"一阶 + 匹配参照"，不要求 DB 也有 E/F 连接，对 D2 是偏严的口径（D2 的事件另外已经过 HC）。
