# P1 committor 射击协议(PLAN 第 2 件)· 判据外的独立探针

**状态:协议冻结于跑前(2026-09-20,决策 3)。实跑需 MACE 机型,约一天机时。**

## 这是什么、不是什么

对 P1(丙二醛分子内质子转移)已 bracket 的幅度窗口,从窗口几何出发打 N 发
有限温度动力学,统计落入两侧盆的比例 p_B,给 `seek_saddle` 选出的 ridge 帧
(本来就是 p_B≈1/2 的 1-sample 代理)**加误差棒**。

**它是独立探针,不是 b04/P1 冻结结果的一部分**(决策 3,用户确认)。
只进模型报告,不进任何判据——与队列第 5 项 b05 的 QM 同一条规矩。

## 射击系综(决策 3)

| 项 | 值 | 依据 |
| --- | --- | --- |
| 系综 | **(a) Maxwell–Boltzmann**,复用 `thermal_momenta(atoms, T, seed)` | committor 的定义系综;(b)(c) 是自造系综无文献对照 |
| 温度 | **T = 300 K** | 项目先例:`P2_TEMPERATURE_SCAN_PROTOCOL.md`、`runs/knob_T300_s17` |
| T = 0 | **拒绝(fail closed,测试钉死)** | T=0 ⇒ 零动量 ⇒ 动力学确定 ⇒ N 发全同,committor 无定义 |
| N | **16 / 窗口** | 见下节分辨率先行 |
| seed | 发间互异、可复现(seed0 + i) | 假 calculator 下测试钉死 |

## 分辨率先行(开跑前写死,不看完结果再定)

N = 16 在 p = 0.5 附近的 95% Wilson 区间约 **[0.28, 0.72]**。所以本批**只回答**
「p_B 是否接近 0 或 1」;**不**分辨 0.5 与 0.25——那需要 N ≳ 50 的后续批,另批。
区间用项目已在用的 Wilson 公式(16/16 → 下界 0.8064 那个实现)。

## 判归(2.2)

每发结局三选一:**A** / **B**(现成 `registry.admit` + `chemical_key` / microstate 匹配)/
**其他**(quench 失败、门拒绝、第三盆)。**其他单独计数,绝不并进 A 或 B**
(规矩:未完成 ≠ 失败;把未完成算进分母任何一边都是制造没测过的数字)。

## 范围守门(2.6)

- **只对已 bracket 的窗口打**,不动全扫描。
- 默认 `committor_shots = 0`(关);配置显式给正值才开。
- 理由:开它是 N 倍试验预算,而 b04 负侧此刻正卡在覆盖上(14/28)。

## 目标窗口

P1 的 0.275 / 0.300 / 0.350(已 bracket 的三个幅度点),各 N = 16 发。

## 落盘(2.4)

`scan["local_brackets"][i]["committor"] = {shots, reached_A, reached_B, other,
p_B, wilson_95: [lo, hi], ensemble: "maxwell-boltzmann", temperature_K}`。
**只进模型报告,不进判据。**

## 顺手结掉的一条(P2 八条:「`a_c` 单调性是假设」)

同一方向的多个幅度各打 N 发 ⇒ p_B(a) 曲线,同一批数据,**只进报告**。
单调性若被破坏(幅度升而 p_B 不升),按观测记录,不改判据。

## 已知风险(跑前记下)

- T>0 后 `max_nve_drift_eV_atom` 这类门在 T=0 下从没被真正考验过,行为要重新量一次。
- 判归的「其他」若显著(>25%),本批 p_B 的解释力按实际分母报告,不悄悄扔。

## 执行结果 · 2026-09-22 · `runs/p1_committor1/`

**跑了，判归有 bug，杀了，落点重判之后有数。** 三件事分开说。

### 1. 首次实跑的报数是假的

四个 bracket 全报 `A 0 / B 0 / other 16`。不是统计不够 —— **A/B 两个分支在代码里到不了**：

1. 判归读 `record["target_microstate"]`，而那个键只有扫描路径在 `registry.admit` 之后才写
   （`search.py:1813`），射击不走那条路。
2. 修好①之后仍是 0：`find_node` 收到的是 `key_of()` 返回的**身份字典**，而 `node.key` 是
   其中的哈希**字符串**，两者比较静默不匹配。

修法：`Registry.identify()`，只读。**不用 `admit`** —— 那会把射击写进它要观测的那张网，
与本协议「只进模型报告，不进判据」直接冲突。指纹 `ec32bc3d` → `63be7064`，
新增测试 `test_a_shot_that_terminates_is_judged_a_basin_not_other`（变异检验过）。

### 3. 结论：ridge 代理有偏，不是有噪声

本协议「分辨率先行」那节写死：N = 16 **只回答 p_B 是否接近 0 或 1**。
**答案是接近 1，四个窗口无一例外。**

`seek_saddle` 选出的 ridge 帧本来是个**假设 p_B ≈ 1/2 的 1-sample 代理**。实测说它已经
越过了分水岭，站在产物一侧。这正是本协议要给的那根误差棒，而它给出的是**系统偏移**，
不是散布。

「已知风险」那两条也有了着落：`max_nve_drift_eV_atom` 在 T = 300 K 下没有产生拒绝；
「其他」在修好判归之后是 **0%**（首跑的 100% 全部是判归 bug，不是未完成的射击）。

### 待落笔：射击点要往低幅度移

要量 p_B ≈ 1/2 的那个面，得在**比现有 bracket 高端更低的幅度**上打。这是对本协议
「目标窗口」一节的修订，**按规矩要在跑之前冻**。成本不高：每个候选幅度 16 发，
上一次的日志显示从起跑到撞上第一个 bracket 只用了 17 分钟。

**在此之前不要把上表读成「committor 测完了」** —— 它测的是三个已 bracket 的窗口，
而那三个窗口现在已知都不在分水岭上。

## 2026-09-23 · 上节结论被推翻：射击被二次扰动了

**「ridge 代理有偏」不成立，原文保留。** `shoot()` 把 ridge 帧交给 `run_trial`，后者又施加了
一遍扰动（扫描的 `probes[0]`，即最低一档粗幅度）。盘上实测，每发首帧：

| bracket | 再施加的扰动 | 首帧多出的能量 |
| --- | --- | --- |
| c000 stretch (4,5) | 0.15 Å | 势能 +0.405 eV |
| c008 stretch (0,5) | 0.15 Å | 势能 +0.491 eV |
| c002 / c006 kick | 0.3 eV | 动能 0.44–0.72 eV（纯 300 K 热动量约 0.15–0.34） |

势垒 419 meV，多推的这一下与势垒同量级。所以 p_B 0.875–1.0 量的是「ridge 帧 + 再推一次」，
不是 ridge 帧。**「射击点往低幅度移」那条待落笔撤回** —— 前提没了；协议本身不改，
窗口与 N 都不动，这次修的是实现没做到协议写的「从窗口几何出发」。

修法：`run_trial(..., deliver=False)` 跳过位移 / kick / pulse，只留热动量；`shoot` 传 False；
射击记录带 `probe_delivery: "skipped:committor_shot"`（普通 trial 记录逐字节不变）。
新测试 `test_a_shot_starts_from_the_frame_it_is_given`，变异检验过（改回 `deliver=True` 即红）。
指纹 `63be7064f9e09f82` → **`4014c4b267b25142`**。
