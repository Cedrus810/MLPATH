### 做什么

#### 1.1 引擎：`src/prrs/canonical.py`（新文件）

个体化-细化（individualization–refinement）。**不写 nauty 的剪枝** —— 本项目最大的群是
b05 反应物的 |Aut| = 1296，朴素 IR 的叶子数与 |Aut| 同量级，而现在的回溯内核是
3889 nodes / 28 ms，所以朴素版的成本落在同一量级内。剪枝是没有实测的慢就没有优化对象
（P0 快速路径那条已经吃过一次这个教训）。

```python
@dataclass(frozen=True)
class CanonicalForm:
    order: tuple        # 正则序：order[k] = 排在正则第 k 位的原子下标
    colours: dict       # 细化到离散前的稳定色（给还需要色的消费者）
    orbits: dict        # atom -> orbit id。CERTIFIED：由枚举出的群得到，不是色类
    group: list         # 自同构，index array，identity 在前、其后字典序（与现在的约定一致）
    certificate: tuple  # 正则序下渲染的边集；同构 <=> certificate 相等
    info: dict          # enumerated / reason / search_nodes / budget_unit / limit

def canonical_form(numbers, edges, index, edge_colours=None, limit=20000) -> CanonicalForm
```

算法，五行能说完：

1. 用初始色（元素）跑 `refine` 到稳定。
2. 稳定色离散 ⇒ 这就是一个叶子，算它的 certificate。
3. 否则取**第一个非单例色类**（按色的字典序，确定性），逐个个体化其成员，递归。
4. 所有叶子的 certificate 取 min ⇒ 正则形式；min 由哪个叶子给出 ⇒ `order`。
5. **certificate 相等的两个叶子给出一个自同构**（两个正则序的复合）。全部收集 ⇒ 全群。

预算单位仍是 `search_nodes`，`limit` 语义不变，**溢出照旧 fail closed**
（`automorphisms` 的 docstring 那句 "An incomplete group is never used" 照搬）。

`refine` 要接**边色**（下一步要用）：签名从
`sorted(labels[j] for j in adj[i])` 变成 `sorted((edge_colour(i, j), labels[j]) for j in adj[i])`。
没有边色时逐字节退化成现在的 `canonical_labels`，这一条要有测试钉住。

`automorphisms()` 改成 `canonical_form(...).group` 的薄包装，**返回值与 info 的字段名一个不改**
（下游 `network.py:311`、`chemistry.py:849` `symmetric_rmsd` 都在消费它）。

#### 1.2 event_key：叠合图的正则形式

**难点先说清楚**：正则序是**一个图**的属性，而事件身份要同时渲染 source 和 endpoint。
两边各自正则化，得到的是两个不相干的编号，没法比较边差。

解法是把事件编码成**一个边着色图**：顶点 = 原子，边 = `source.edges ∪ endpoint.edges`，
边色三选一 —— `kept` / `broken` / `formed`。对这个边着色图求正则形式，
在它的正则序下渲染 broken 与 formed。方向无关照旧：把 `broken ↔ formed` 对换再算一次，取 min。

这正是 1.1 里 `refine` 要接边色的原因，也是为什么这一步**必须**在 1.1 之后。

**落盘形式（推荐，见文末决策点 1）：加字段，不换 `key`。**

```
key              不动          编号内身份，加限定说明
structural_key   新字段        叠合图正则形式的摘要 —— 跨 run / 跨 build 有效的那一个
canonical        不动
structural_form  新字段        正则序下的 (broken, formed) 渲染
```

这样 digest 零差异、b04 的冻结判据一个字不用改、`xfail(strict)` 那条测试改成断言
`structural_key` 在重标号下不变（会通过 ⇒ **同一次改动里摘掉标记**，strict 一旦意外通过本身就是失败）。

### 第 0 步不是写代码，是选射击系综

**实测：`temperature_K = 0.0` 在 b04、b05、P1 的每一次运行里。**

```
runs/p1_malonaldehyde   T=0.0   seed 17
runs/b04_frozen1        T=0.0   seed 42
runs/knob_T300_s17      T=300.0          <- 唯一的 T>0 先例
```

T = 0 ⇒ `thermal_momenta` 给零动量 ⇒ 动力学完全确定 ⇒ **同一几何打 N 发得到 N 个相同结果**。
在这上面算 committor 是算一个恒等于 0 或 1 的量。所以三选一：

| | 是什么 | 代价 |
| --- | --- | --- |
| **(a) T > 0 的 Maxwell–Boltzmann**（推荐） | 文献里 committor 的定义本身。项目已有 T=300 的协议（`P2_TEMPERATURE_SCAN_PROTOCOL.md`） | 改 T 就是改 config ⇒ **这是一次独立探针，不是 b04 的重跑**，不得混进冻结结果 |
| (b) T=0 + 在正交于反应坐标的子空间里注入固定动能的随机方向 | 保持 T=0 的其余语义 | 系综是自造的，没有文献对照，要自己论证 |
| (c) 不动动量，随机小位移扰动几何 | 最省 | 量的不是 committor，是别的东西 |

## 3. 完备性证书

### 现状

membership oracle **已经有了**：quench（`runner.quench`）+ `Registry._match_microstate`。
缺的是命题、覆盖、和梯度界。

`SESSION_2026-09-13.md` §3.4 已经把话收窄过一次，照抄不改：
抽样 ∂N(A) 给的是**上界**（存在性），不是下界；要说「X 以下不存在」得证一个集合为空；
对的对象是**次水平集连通分支** `A_X`，`A_X ⊆ N(A)` ⟺ 每点 quench 回 A；
产物是**给定覆盖半径 δ 与实测梯度界 L 的条件证书，不是定理**，且**只能在子空间上声明**。

### 做什么

#### 3.1 命题先落笔（这条是数学，要你写）

建议形式，空格里的东西要你填：

> 设 V 是由 ⟨哪些坐标⟩ 张成的 d 维子空间，B 是 V 内以 A 的极小点为心、半径 R 的球。
> 取覆盖半径 δ 的点集 S ⊆ B，对每个 s ∈ S 实测 quench 后落回 A。
> 设 L 为 B 内**实测**的梯度 Lipschitz 上界。则在 ⟨什么条件⟩ 下，
> B ∩ V 内不存在能量低于 X 且不属于 A 的次水平集连通分支。

**不要让代码去声明一个没写清楚的命题。** 代码只负责产出 δ、L、V、R 四个量和那张 membership 表。

#### 3.2 三个函数

```python
def cover(centre, basis, radius, delta)      # d 维低差异序列或格点
def membership(point, factory, config)       # quench + match，包已有的
def gradient_bound(points, energies, forces) # 相邻点的 ||∇E|| 差 / 距离，取上确界。实测，不是假设
```

**成本在 d 上指数，这是硬的：** δ = 0.1 Å、R = 1 Å ⇒ 每维 20 点。

```
d = 2      400 点
d = 3    8 000 点
d = 4  160 000 点
d = 6    6.4e7 点     <- 不可能
```

所以计划里写死：**d ≤ 3，且 V 必须是被论证过的子空间**（例如反应坐标 + 两个最软模），
声明里必须带 V 的构造方式。

#### 3.3 产物

一份 JSON + 一段声明文本。**声明里 δ、L、V、R 四个量缺一不可** ——
缺任何一个就不发证书（fail closed）。

### 验收

**先在解析势上做完整链条**（二维双阱，力和 Hessian 都是解析的），再上 MACE：

- 证书对已知答案成立。
- **把 δ 放大到已知会漏掉第三个阱的值时，证书必须失败。** 这是这一件的变异检验，
  没有它就只是一个会输出「通过」的函数。

### 风险

最贵的一件，而且 malonaldehyde 419 meV 是一个体系判生死。
建议：解析势链条跑通、变异检验绿了之后再决定要不要上真体系。

### 量

~200 行 + 大量机时。**文章最高，代价也最高。**

## 4. `network.json` schema 显式化 —— 最便宜的结构性收益

### 现状

#### 4.4 锚

## 5. 碎片平动（B″）+ b05 诊断

### 现状

- `internal.py:398` `rotate_rigid` 已有，精确（碎片内距离变化 0.00e+00 已测）。
- `runner.py:1664` `polish_soft_modes` 的脚注 [1] **明确写了平动为什么没做**：

  一套阈值机制被喂进两个单位制是静默的那种错误」。这句话是对的，计划要照它办。
- B 的实测（`SESSION_2026-09-13.md` §4）：定义域缺口是真的、已关闭、但**鞍点不动**，
  残余 −54 cm⁻¹ 是**耦合的碎片间运动**。

### 做什么

#### 5.0 先跑零代码的诊断

`DECISIONS_PENDING` 的原诊断**依然成立**且不需要写一行代码：
放开 `quench_steps`（现在 500）与 `irc_relay_hops`（现在 3）重跑那六条下降。
**B 不是它的替代品。** 先做这个再决定 5.1 要不要写。

#### 5.1 `internal.translate_rigid`

比 `rotate_rigid` 简单：平移 `members`，之后按总 COM 还原（还原是平移，不动任何内坐标）。~20 行。

#### 5.2 `perturbations.fragment_translations(atoms, graph)`

每个碎片三个方向。**用什么基是决策点 5**：

| | 理由 |
| --- | --- |
| **碎片间质心连线 + 两个正交方向**（建议） | 耦合的就是相对位移，这个基直接对着它 |
| 惯性主轴 | 与 `fragment_rotations` 一致，但主轴是**朝向**的属性，不是**相对位置**的 |

#### 5.3 三个新阈值，每个都要一次测量

```
fragment_translation_curvature_floor_eV_A2
fragment_translation_tolerance_A
fragment_translation_step_A
```

**规矩：旋钮先验证再设计实验。** 测法：在 b05 那三个 order-1 端点上扫碎片相对距离，
量曲率的量级，从实测的量级定地板 —— 不是从弧度那套换算过来。
三条都要进 `RATIONALE`，理由各自是一次测量。

#### 5.4 tier 判定按单位分流

把 `polish_soft_modes` 里的 tier 判定抽成

```python
def _tier(curvature, gradient, floor, cap, tolerance) -> (str, note)
```

弧度一套常数、Å 一套常数分别传入。**这一步是 5.3 的前提** ——
不抽出来就是把两个单位喂进同一个阈值，正是那条脚注点名的错误。

### 验收

- 碎片内距离变化 0.00e+00（B 已经这么验过，照办）。
- b05 三个端点的 saddle order 与虚频**重测**，与 B 之后的 order 1 / −54 cm⁻¹ 对照。
- digest：新坐标只在多碎片结构上出现。**先查语料里有没有多碎片帧** —— 有就不是零差异，要先量。

### 要你先落笔的

- 决策点 6（B′，独立于本件但同一处代码）：打磨要不要对精确周期坐标扫过负曲率。

## 6. 扫描续跑 —— 先写等价性测试，写不出来就不做

### 现状

```
search.py:568   if output.exists() and any(output.iterdir()): raise FileExistsError
runner.py:2787  directory.mkdir(parents=True, exist_ok=False)
```

一次外部中断丢掉在飞的全部工作。`HANDOFF.md` §9 自己写着：
「要做需重建 registry 状态，而**接纳顺序会影响结果**，做错比不做更糟。」

顺序依赖具体在哪三处（都在 `network.py`）：

| 位置 | 依赖什么 |
| --- | --- |
| `_match_microstate:369` | **顺序遍历，首个命中即返回** |
| `_insert:406` | id = `len(microstates) + len(evicted)` |
| `admit` 的水库分支 `:339` | 驱逐依赖到达序与 `score` 的历史 |

### 做什么

#### 6.1 先写这条测试，它是整件事的前提

```
跑一个 N 步的小 run
  -> 从它的落盘重建 Registry
  -> 断言重建出的 Registry 与原地内存里的那个逐字段相等
     （node id / key / depth / permutations / microstate id / trials_spent
      / outcomes / score / evicted 列表 / conformer_transitions）
```

**写不出来就停在这里，不要做续跑。** 例如 `score` 依赖浮点历史、或 `permutations` 的
顺序不可重建 —— 那都是「做错比不做更糟」的实例。

#### 6.2 `Registry.from_network(network, output, config)`

纯读盘重建。结构在 `chemical/*.extxyz`，`summary()` 已经把 microstate 需要的字段全落了。

#### 6.3 `Search.run(..., resume=True)`

不再拒绝非空目录，改成三条硬前提，**任一不满足就拒绝**：

1. `network.json` 存在且 `status != "done"`。
2. `config.json` 的 `experiment_sha256` **逐字节相同**。
3. `implementation_sha256` **相同**。换了实现的续跑就是混批，本项目已经因此作废过一轮
   （`HANDOFF.md` §9：107 个 run 摊在 16 个实现指纹上）。

#### 6.4 队列要新增一个落盘字段

`queue` 不在盘上，重建不出来。每次 `publish()` 写
`network["queue"] = [[node_id, microstate_id], ...]`。
**这是这一件唯一必须新增的字段**，它会动 schema（正好是第 4 件先做的理由）。

#### 6.5 半成品 trial 目录

`t000042` 可能 mkdir 成功而 `result.json` 没写。续跑时删掉**最后一个**没有 `result.json`
的 trial 目录，从那个编号继续，并把这件事记进 `network["resume_log"]`。
删除是唯一一处会动已落盘数据的地方，所以它要留名。

### 验收

**只有一种形式**：一个 run 跑到一半 kill → 续跑 → 与不中断跑完的结果
`network.json` / `attempts.jsonl` **逐字节相同**。不相同就是 6.1 那条测试没覆盖到的顺序依赖。

### 风险

如果 6.1 写不出来，这一件**放弃**，并把「为什么写不出来」记进 `DECISIONS_PENDING`
—— 那条记录比续跑本身更有价值。

~200 行，其中 6.1 那条测试是最难的部分，也是唯一不能省的部分。
