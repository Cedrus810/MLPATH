## 0. 来由与范围

MLPATH 按信息条件分三种模式：

| 模式 | 已知 | 未知 | 问题 |
| --- | --- | --- | --- |
| `discover` | R | P、TS、机理 | R 附近可能发生什么（**即现在的 PRRS**） |
| `connect` | R、P | TS、路径、中间体 | 找把 R 和 P 连起来的反应通道 |
| `handoff` | R/P 或部分机理 | 电子结构上解释不了的那一段 | 哪里必须交给 QM |

**本计划只做 `connect`。** `handoff` 不在本计划：它和搜索目标正交（对 discover / connect 的路径都适用），
更像一层标注，而且现在没有任何「电子风险分数」（`reliability.py` 只有几何守卫）。以后另立。

`connect` 由两个工程组成：

- **工程一 · 化学态图桥（上层）**：在 `chemical_key` 构成的离散图上决定**下一步去哪个化学态**。
- **工程二 · 原子 Langevin 桥（下层）**：一条边内部的条件动力学，目标是**进展集合**（§1 第 4 条）。

两者共用一个**测试台**（§2），先建测试台，再分别推进。

## 1. 本次对话已定的（2026-09-28）

1. **产物只决定先后，不当过滤器。** P 不进 `chemical_key`，不进 admit，不进任何 gate，不决定一个盆地收不收。
   connect 跑出来的网络和 discover 是同一种东西，证据层级照旧。
2. **两层桥**：化学态图桥 + 原子 Langevin 桥。全局的 h 沿图上的路径分解成一步一步，每一步交给原子层。
3. 原子层用欠阻尼 Langevin，Doob 修正只加在动量通道：
   $dp = [-\nabla U - \gamma M^{-1}p + 2\gamma k_BT\,\nabla_p \log h(q,p,t)]\,dt + \sqrt{2\gamma k_BT}\,dW$。
4. **原子桥的目标集合 = 进展集合**：$B_\text{step} = \{x : d(G(x), G_P) < d(G_\text{当前}, G_P)\}$。
   「d 要先变大、再变小」的中间体由上层兜底：**上层不剪枝**，不前进的态照样留在队列里。
5. **默认模式是 `discover`，行为逐字节不变**：connect 的所有改动默认关，digest 零差异。
6. CLI 形状：`prrs search --mode discover|connect [--product P.xyz]`。handoff 不占模式名。
7. **加一个两端版本**（§4½）：R、P 都给定且认为是**一步**反应，只求 TS。原子桥的目标直接取 P 盆地，
   不取进展集合。很多实际问题就是这个形状（产物已知、TS 未知），而且仓库里有冻结的真实参照可以对。

## 3. 工程一 · 化学态图桥（上层）

## 4. 工程二 · 原子 Langevin 桥（下层）

**核心难点写在前面**：Doob 修正需要 $\nabla_p \log h(q,p,t)$，而 h 就是（带时间、定义在相空间上的）committor。
公式是对的，**难在 h 从哪来**。便宜的近似 h 会退化成朝目标拉的弹簧，再靠 Girsanov 权重还原，
而在稀有事件、高维、低温下权重会退化。所以本工程先在测试台上**用精确 h 验证机器**，
再单独研究**近似 h**；后者是研究问题，本计划不预设它一定成。

## 4½. 两端版本：已知 R 和 P，求 TS（试做）

**问题形状**：R、P 两个结构都给定（原子编号一致，同 K4），认为 R→P 是一个基元步，要的是 TS 和通道。
这是工程二的一个**特例**：原子桥的目标集合直接取「`chemical_key` = P」的盆地，而不是进展集合。

**为什么值得单独试**：

- **问题最良定**：两个已知盆地之间的 h 就是 committor，仓库已经有整套 committor 机器
  （`runner.shoot`、首次进入 `committor_entry_steps`）。`run_trial` 的 `first_entry` 现在接的就是
  `{标签: 键集合}`（`runner.py:2843`），**两端版本不需要 L1 的谓词推广**。
- **有冻结的真实参照**：P2（3-氧代丁醛 A→B，TS 虚频 −3010 cm⁻¹ 一带、势垒 +361 meV）
  和 P1（丙二醛，committor 数据在 `runs/p1_committor2` 与首次进入确认批）。
  验收拿桥的结果**对照**这些冻结结论，冻结结论本身一字不动。
- **自带「不是基元步」的诊断**：如果桥轨迹在中途某个盆地停留（沿路径淬火得到第三个 `chemical_key`），
  就说明 R→P 不是一步。这时如实报告「经过中间体 X」，把问题交回 connect 的多步版本，而不是硬连。

**输出**：条件路径系综 → 取 h ≈ 1/2 附近的帧（用已有的射击核对）→ 交给现有的鞍点搜索与双侧下降
（`seek_saddle` / `descend_saddle`）→ `ts_support` 核对两侧确实落在 R 和 P。
TS 的位置由现有机器定，桥只负责把种子送到势垒附近。

## 5. 依赖顺序

```
T0 → T1 → T2
 │
 ├─ 工程一：G0 → G1 → G2 ─┐
 │                  G3 ───┴→ G4 → G5
 │
 ├─ 工程二：L0 → L1 → L2 → L3 → L4 → L5（并入 G5 的比较）→ L6
 │                      │
 └─ 两端版本：    E0 ───┴→ E1 → E2 → E3（与 L4 共用近似 h）→ E4
```

G0–G5 不依赖工程二，可以先做完、单独给出结论。L0 / L1 不依赖 T，可以和 T0 并行。
两端版本不需要 L1，只要 L0 + L2 就能开 E1；E3 可以早于 L6，当作近似 h 的第一个真实体系。
**L4 是整个计划里唯一可能「做不成」的一步**；它不成，工程一照样成立（I-a + I-b 就是一个完整的 connect），
原子桥停在「测试台上精确 h 可用」这一结论。

## 6. 风险

| 风险 | 后果 | 应对 |
| --- | --- | --- |
| 多步 discover 在 G0 暴露出一批缺陷（深度账本、预算、续跑） | 工程一推迟 | 这些缺陷本来就在，只是 depth 1 看不到；按现有规矩逐条单独修，不混进 connect |
| $d$ 在对称性下算不动（产物的自同构群大） | G1 卡住 | 复用 `canonical.py` / `chemistry.automorphisms` 的剪枝枚举与预算；溢出时 fail closed，不拿恒等置换充数（同决策 7） |
| I-a 在 T-绕路上卡死 | 第 1 节第 4 条的兜底不成立 | 这正是 G5 要测的；卡死就如实记录，再定上层要不要留一份 discover 式预算 |
| L4 所有候选的 ESS 都塌 | 原子桥在真实体系不可用 | 见 §5：工程一不受影响 |
| Langevin 的 γ、T 成了新的调参面 | 违反「不许边跑边改」 | K7 跑前定值；要改走显式修订 |
