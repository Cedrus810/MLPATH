# 05 怎么跑，以及怎么读结果

## 5.1 两个环境，故意的

```makefile
PYTHON ?= /home/ruigengji/miniforge3/envs/openmm_dev/bin/python   # 科学环境
RUFF   ?= .venv-tools/bin/ruff                                    # 开发工具
```

`openmm_dev` 是**科学环境**，它的版本号是每一个结果的一部分——后端 parity 曾经因为
openmm 的一个 patch release 变红过。所以**任何仅仅是开发便利的东西都不许装进去**。
ruff 住在 `.venv-tools`，它存在的唯一理由就是让"格式化"永远不可能移动 openmm / torch / mace。

常用目标：

```
make tools      建 .venv-tools 并装 ruff
make fmt        格式化 src/ 和 tests/
make lint       ruff check
make test       pytest（需要科学环境）
make digest     golden-sample 门；改 src/prrs 前后都要跑
make check      lint + test + digest，按这个顺序
make hash       一次 run manifest 会记录的 implementation_sha256
```

`digest` **不在** `test` 里，因为它更慢并且回答的是另一个问题：pytest 问代码对不对，
它问**还能不能产生和磁盘上已有的 run 相同的数字**。有意要移动那些数字的改动带 `--allow` 通过。

## 5.2 跑一次

三个子命令：

```bash
# 1) 离线解析双阱基准（软件基准，不是化学验证）
python -m prrs demo --output runs/demo --seed 42

# 2) 真实搜索
python -m prrs search input.extxyz \
    --output runs/my_run \
    --config config.json \
    --calculator mypkg.mod:make_calculator \
    --calculator-kwargs kwargs.json

# 3) 把一条已接受的通道导出成局部精化的初猜
python -m prrs export-path --run runs/my_run --attempt t0042 \
    --output seed.extxyz --images 9
```

几点：

- `--calculator` 是 `module:function`，返回一个 ASE Calculator。**必须显式指定**——
  没有默认势能面。
- 输出目录必须是**新的或空的**，不会覆盖。
- `export-path` 只用 source + 物理轨迹 + endpoint（淬火迭代不是 MD），按**弧长**
  等距重采样。它的输出 `info` 里刻着
  `"warning": "Unrefined interpolated path seed; not a TS, MEP or barrier"`。

`demo` 用的是一个合成径向双阱，**明确不是碳化学**，所以它把 `closed_shell_only`
关掉（价键判据对它无话可说）。它验收的是算法与数值实现，**不能证明真实反应发现能力**。

## 5.3 输出目录

```
runs/my_run/
  config.json        manifest：完整配置 + 后端版本 + 三个哈希 + 单位 + scope + 各种 policy
  input.extxyz       输入结构（带电荷/自旋戳）
  network.json       网络快照，每次 publish() 覆盖写
  failure.json       只在崩溃时；纯字符串，网络序列化失败也活得下来
  chemical/          每个 microstate 一个 .extxyz
  ts_candidates/     通过认证的一阶鞍点
  trials/<id>/
     result.json         这次 trial 的完整记录
     response.traj       ASE 轨迹
     observations.jsonl  每个采样帧的观测量
     raw_endpoint.extxyz 淬火前
     endpoint.extxyz     淬火后（info 里带 quench 报告）
     rejected.extxyz     被门拒绝时的结构（`ood` 时同时记为 qm_candidate）
     error.txt           异常 traceback
```

manifest 里的三个哈希：

| 字段 | 含义 |
| --- | --- |
| `input_structure_sha256` | 输入结构 |
| `implementation_sha256` | `src/prrs/*.py` 全部源码的哈希（`make hash` 可查） |
| `experiment_sha256` | 上面全部内容 + 配置 + 后端版本的哈希 |

`versions()` 会额外做一件事：有些 conda 包不带 Python distribution metadata
（openmm-ml、openmm-torch、nnpops 三个都装了且可导入，`importlib.metadata` 却报 None），
所以它回退到 `find_spec` 做**存在性**测试，记 `"installed; no version metadata"`。
用 `find_spec` 而不是真 import，是为了写 manifest 这件事永远不会把 torch 拉进进程。

**崩溃处理的顺序是有讲究的**：先写最小的 `failure.json`（纯字符串），再写 manifest，
最后才 best-effort 地写网络快照。旧的顺序在"异常本来就来自 publish()"时会再抛一次同样的错，
manifest 永远写不出去，`status` 停在 `"running"`——**读起来跟被信号杀掉一模一样**，
这在温度扫描的三个 seed 上造成过一次错误诊断。

## 5.4 每次力评估都要过的门

`reliability.GuardedCalculator` 包住物理 calculator，**包括 FIRE 淬火内部的每一步**。
任何一条不满足就抛 `GateRejected`：

| code | 判据 | 默认 |
| --- | --- | --- |
| `nonfinite` | 坐标 / 能量 / 力有限 | — |
| `overlap` | $d_{ij} \ge$ `min_distance_ratio` $\cdot (r_i^{\rm cov}+r_j^{\rm cov})$ | $0.45$ |
| `force_limit` | $\max_i \lVert F_i\rVert \le$ `max_force_eV_A` | $100$ |
| `energy_limit` | $(E - E_{\rm ref})/N \le$ `max_energy_rise_eV_atom` | $20$ |
| `invalid_uncertainty` | 不确定度有限且非负 | — |
| `uncertainty_unavailable` | 要求了不确定度但 calculator 不提供 | — |
| `ood` | $U_F \le$ `max_uncertainty_eV_A` | `None`（不启用） |

轨迹层另有一条（在 `run_trial.observe` 里）：

| `nve_drift` | 自由段 $\lvert E + K - E_0\rvert / N \le$ `max_nve_drift_eV_atom` | $0.1$ |

不确定度的两个候选度量是 ensemble 力分歧 $U_F = \operatorname{Var}[F_1,\ldots,F_M]$
和嵌入空间距离 $U_z = d(z, z_{\rm train})$。当前只支持 calculator 通过
`results["force_uncertainty_eV_A"]` 报出的前者，**默认不启用**（`None`）。
被 `ood` 拒绝的结构会被标成 `qm_candidate`——这就是**主动学习**接口预留的位置。

**可靠性门是防止把 MLP 外推伪影当成化学的唯一手段。** 这一点在通用 MLP 上尤其重要。

## 5.5 一条 reactive 结论要过的关

从"轨迹末端图变了"到"网络里多一条边"，中间有这些：

1. **附带损伤门**（几何探针）：非目标键变化、最近距离比、碎片数；
2. **NVE 漂移门**：自由段是无偏置的，能量必须守恒；
3. **tail persistence $\ge 3$**：新键图必须在自由 MD 的**最后三步**都维持住，否则
   `status = "unconfirmed"`，`failure.code = "transient_topology"`。
   但**端点不被丢弃**——它仍是一个完美的驻点，而产生它的幅度是**离分界面最近的那个**，
   正是鞍点可及的地方。在丙二醛上，$0.35\ \mathrm{\AA}$ 的探针穿越了、被整个丢掉，
   于是 60 次 trial 里一个过渡态都没找到。
4. **淬火收敛**：FIRE 达到 `quench_fmax_eV_A` **且**软模抛光满意**且**抛光没有移动几何；
5. **`confirm_minimum`**：Hessian 谱 + 刚体地板门 + `internal_mode_recheck`；
6. **`Registry.admit`**：`chemical_key` 决定去 microstate 还是开新化学节点；
   模型域声明可能拒绝。

被 `confirm_minimum` 接受、却被化学标注拒之门外的极小，**不会消失**——它们进
`network["withheld_candidates"]`，因为"标注器叫不出它的名字"不是它停止存在的理由，
而一个 QM 验证 pass 需要找得到它们。`_WITHHELD_MEANING` 说明有两个来源：
标注拒绝，或者极小检验没能读到每个方向（`confirmed_minimum` 字段说是哪一个）。
两种情况下结构都保留——**这个排除是关于标注器、模型声明或一次不完整测量的陈述，
从来不是关于那个极小在不在那里。**

## 5.6 已有的结果

| 基准 | 体系 | 检验什么 | 判定 |
| --- | --- | --- | --- |
| P0 | 乙醇 | 构象发现与架构 | 通过；`reactions` 一直是 0 |
| P1 | 丙二醛烯醇 C₃H₄O₂ | 退化质子转移；自同构商既不造假产物也不吃掉真事件 | 通过 |
| P2 | 3-氧代丁醛 C₄H₆O₂ | 跨节点反应 $A \to B$ | 第一轮**失败**（反应坐标从未被采样），定位机制后通过 |
| P3 | 苯甲酰丙酮螯合烯醇 C₁₀H₁₀O₂，22 原子 | 双侧连接的完整 TS 认证 | **模型限定通过** |

**P2 第一轮的失败值得每个新人读一遍。** 判据 A 组全灭，原因不是"这次没抽中"：
方向在家族内是**均匀抽**的，于是承载反应的那根 O–H 在 3-氧代丁醛的 11 根键里
只有 3-in-11 的机会被采到，而且没被采到。这个失败模式**随体系变大系统性恶化**。
处理方式是记成"**失败 + 已定位的机制**"，而不是换个 seed 拿绿灯——
"换 seed 拿绿灯就是边跑边改"。修法是 §2.7 的分层方向预算 + 氢键先验。

**P3 的结论与它必须一起说出去的限定**：在 MACE-OFF24_medium 上
$A \leftrightarrow \mathrm{TS} \leftrightarrow B$ 的双侧连接成立，
$+316\ \mathrm{meV}$（$315.9$–$316.8$）是**该模型上**的 $A \to B$ 势垒，
虚频约 $-3086\ \mathrm{cm^{-1}}$。限定：

1. **$316\ \mathrm{meV}$ 是 MACE-OFF24 上的值。** 三个模型实测
   $+316.3 / +84.8 / +96\ \mathrm{meV}$，**差 3.7 倍**。三个 MLP 一致也不等于对。
   绝对值的去处是下游 QM。
2. **那是同一个鞍点族命中 6 次，不是 6 个不同的 TS。** 三个 amplitude 之间只差
   $0.9\ \mathrm{meV}$ / $1.8\ \mathrm{cm^{-1}}$。
3. 命中率 6/16 是**观察项，不是判据**（判据 D4 明写"不要求所有 seed 成功"）。
4. **曲率的"准"仍然没有外部对照。** 无参考诊断只能查不一致。

判据冻结的纪律也要注意：**P1/P2 的判据冻结在第一次搜索运行之前**（P2 连 preflight
结果都还没有）；**P3 是一次事后冻结**，文档明写"它比 P2 的预注册弱，这一点不打算用
措辞掩盖"，并用可查的时间顺序说明它仍不是"照着结果写判据"。

## 5.7 不成立的说法清单

拿这个仓库的结果去写东西之前，逐条对照：

**关于搜索**

- ❌ "这些是 $A$ 能做的全部反应" —— 提案基**故意不是** $3N$ 的基。没有任何东西估计
  覆盖率。唯一支持的读法是"**搜索找到了这些反应**"。
- ❌ "$a_c$ 是活化能" —— $a_c \ne \Delta G^\ddagger$。它是同一扰动家族内可比的
  **可及性得分**。
- ❌ "幅度越大越容易反应" —— 实测存在 `nonmonotonic_return_observed`。
- ❌ "探针跨过了它瞄准的坐标" —— `high_kind == "boundary_unattributed"` 只说
  **到达了某个盆地边界**。

**关于曲率**

- ❌ "$\kappa_a$ 的本征值" —— 有限 $a$ 下响应既非线性也非对称，**没有算子，也没有谱**
  （03 章 §3.8 有实测）。只有 `method == "hessian"` 时那些数才真是本征值。
- ❌ "$\sigma$ 小所以结果可信" —— $\sigma$ 是 OLS 残差尺度，**看不见方向错**。
  实测过 $\sigma = 3.7\times10^{-6}$ 而值错 $0.18$。
- ❌ "刚体地板通过了所以 Hessian 是对的" —— 那是**必要条件**，对内部子空间零信息。
- ❌ "全正本征值证明是极小"（`probe` 方法下）—— 负值是决定性的，全正不是。
- ❌ "$\nu_a$ 随 $a$ 单调" —— 实测两个方向都可能。

**关于 TS**

- ❌ "找到一阶鞍点 = 证明了 $A \to B$" —— 还需要**同一个鞍点几何**的两侧下降分别落到
  $A$ 和 $B$ 的 `chemical_key`。两侧落到同一个节点**不得**记为连接成立。
- ❌ "TS 连接给出有向反应边" —— $\Phi$ 给的是无向关联。
- ❌ "势垒" —— 在双侧连接全部成立之前，只能写成"**候选鞍点相对 $A$ 的高度**"。
- ❌ "响应分析佐证了 Hessian" —— 它是用 Hessian 的本征向量做种子的。
  真正独立的第二读数只有 `_independent_response_reading`（seed 化随机起步），
  而且它**只上报、从不门控**。

**关于模型**

- ❌ "三个模型一致所以对" —— 跨模型分歧是**结果**，不是待消除的噪声。
- ❌ 拿 MACE-OFF24 做任何阴离子化学 —— 它对总电荷**逐位无响应**。
- ❌ "标注器解析不了所以是域外" / "解析得了所以是域内" —— 两个方向都不成立。

## 5.8 想改点什么？先读这三处

1. **`config.py` 顶部的桶列表**（`INTEGER_POSITIVE` 等）。每一个数值字段必须**恰好**
   出现在一个桶里，`test_validation` 钉这一点。曾经漏过一次：min-mode 爬升、响应下降和
   鞍点搜索新加的十个字段一个桶都没进，于是 `min_mode_refresh = 0` 在一小时后的
   run 深处变成一个裸的 `ZeroDivisionError`。**在这里命名，就让遗漏变成一个失败的测试
   而不是一场崩溃。**

2. **那些 `_*_MEANING` 常量**。它们是**输出契约的一部分**，改一个是 schema 变更，
   不是改注释。

3. **`make digest`**。改 `src/prrs` 之前和之后各跑一次。
