## 3. 首要算法问题：先修扰动，再评估扫描策略

### 3.1 非目标键损伤来自当前位移实现；不应直接放宽 gate

证据：`src/prrs/perturbations.py:153` 把 bond 位移交给 `internal.displace`；`collateral_metrics` 在第 205 行附近已经豁免目标键。b04 的 `stretch [0,1]`、0.6 Å 扰动因非目标 C–H 键 `[0,4]` 变化 0.0502946 Å 而被拒绝。已有诊断确认交付时只移动 C 和 Cl，所连 H 未随同移动。

优先方案是为适用的桥键设计按图切分的片段位移，按片段质量分配位移；目标键变化必须达到要求，同时保持片段内部几何。跨碎片接近、环内键及集体运动不能机械套用同一种切分，需要明确适用条件和回退方式。禁止针对 SN2 预先指定两个 C–Cl 为反应坐标来绕过发现任务。

验收先用几何级小测试：目标位移准确、非目标键不被无故拉长、质心保持、原子重编号下行为一致，且人为损伤仍会被 collateral 拒绝。之后单独命名这一项干预，在固定配置/seed/预算下比较。原先会反应的 1.0 Å 轨迹是否仍会反应必须重测，不能由几何改善推断。

### 3.2 b04 没有 bracket 的直接原因是拒绝点隔断有效相邻样本

落盘扫描：

| 幅度 | 状态 | 微态结果 |
| --- | --- | --- |
| 0.1 Å | completed | 回到 m0000 |
| 0.3 Å | completed | 回到 m0000 |
| 0.6 Å | rejected / collateral_bond | 未知 |
| 1.0 Å | completed | 到达 m0001 |

`src/prrs/search.py:1361` 只比较原始粗扫描中相邻样本。因此 0.3/0.6 和 0.6/1.0 都不满足“返回/离开”。“只在最大一档离开，所以没有下一档可比”不是准确解释：若前一档有效返回，现有实现已能与最大档形成 bracket。

先修 3.1，再测相同阶梯是否形成有效 bracket；它与能量上限是不同控制路径，但与 collateral 拒绝不是完全独立的问题。

后续如果仍需处理缺测区间，应把“返回 / 离开 / 无效或未知”显式区分。预算内探查未知区间、保持所有拒绝记录并报告未解决区间；不要把 rejected 当返回，也不要直接跳过它并声称已经取得可解释的局部边界。幅度上限扩展需作为另一项干预，预先定义预算及停止条件。

### 3.3 能量上限是当前探针范围，不是可直接推广的参数答案

两个 b04 探针均实际执行 64 trials、20 条扫描，55 completed、9 rejected、1 次 reactive。第二轮仅把相关探索范围放宽后，TS 候选从 0 变 1，bracket 仍为 0。记录显示原始种子相对参考能量高 1.54793 eV，1.5 eV 上限在第 0 步阻止搜索；第二轮经过 17 步得到 order-1 候选。

10 eV 是探针配置，不是已验证的生产默认值。按现有决定继续收集 B 组的路径最大能量、失败方式及成本，再冻结适用范围；不要仅据 b04 成功改变全局阈值。

## 5. 工程缺陷与复现基础

### 5.1 发布失败会阻止失败状态落盘

`src/prrs/search.py:1475` 的异常分支先在内存中设置 failed，然后调用 `publish()`，最后才写 `config.json`。若异常本就来自 `publish()` 的非有限值序列化或持续写入故障，再次 publish 会抛错，后面的失败 manifest 永远不执行。`io.py` 的严格 JSON 检查能定位字段，但不能替代这个恢复机制。

本轮直接提取该 AST 异常分支，以会抛 ValueError 的 publish 执行：内存 manifest 为 failed，manifest 写入调用次数为 0。此复现不依赖科学环境，也没有改写运行数据。

修复应保证独立的最小失败记录先尝试落盘，网络快照保存采用单独的 best-effort 路径，保留原始异常及次级保存异常。磁盘完全不可写时不能保证文件成功，但不能再被网络数据错误阻断另一条可写路径。

验收：网络包含 NaN 的 publish 故障、一次性写入故障、持续写入故障；检查失败记录、原始异常和已有结果不被覆盖。

### 5.2 先建立可复跑的版本，再拆大函数

`ReactionSearch.run` 当前位于 `search.py:367–1482`，共 1116 行；交接中的 837 行是历史数值。它捕获多份可变注册表和运行结果，适合先补编排层行为测试，再按扫描、候选、证据写入逐步拆分。

当前 `.git` 空目录无法保存版本；源码 hash 可以识别实现，但不能恢复旧源码。需要真实版本控制，保存代码/配置/协议及迁移记录，并在独立运行目录记录这些版本。`Makefile` 默认解释器仍是原 Linux 环境；Windows 当前可复现入口尚未建立。`pyproject.toml:9` 引用的根目录 `README.md` 缺失，也应补齐入口说明。

适合补的测试是编排契约：无效中点如何终止/继续扫描、候选标签失败如何保留、不同事件的 TS 支持是否分开、运行失败如何落盘。digest 守护身份字段，不能代替这些行为测试。

## 7. 并行审查补充：优先修正确性，再调效率

### 7.1 候选清单覆盖不完整

search.py:764–794 的 TS 两侧下降与 search.py:1120–1147 的 boundary continuation，在 Registry.admit 拒绝端点时只记录原因，没有写入 withheld_candidates，也没有在拒绝分支写独立最终端点文件及引用。路径轨迹可能保留部分几何，但不能替代统一 QM 候选出口。

统一候选保存入口：记录结构、是否确认 minimum、试验/TS 来源、方向、拒绝层级和原因，再决定网络准入。分别测试普通端点、TS 下降、boundary continuation 的标签/预算拒绝，保证清单和文件都存在。

### 7.2 probe 验证可能把不完整测量当通过

runner.py:2568–2582 捕获某方向 GateRejected 后继续；最终 confirmed = bool(measured) and not negative。其他方向非负时，被拒绝测量的方向不会阻止通过。此问题仅针对 minimum_check="probe"，没有证明默认 Hessian 路径或冻结实验受影响。

应将协议不完整标为未认证，保留拒绝原因和候选；若采用有界缩步重试，应单独定义规则。即使采样全部通过，也不能称为完整 Hessian 证明。验收至少有一个方向拒绝、其余正曲率，要求不再完整确认。

### 7.3 bracket 元数据可能滞后

search.py:1366–1403 细化更新 high_record 时，对 completed departure 没有同步更新 target_microstate/high_kind。粗扫描高端是 boundary/transient、细化后变成已确认产物时，可能保留旧值。应统一刷新高端全部派生字段，并覆盖高端状态及微态变化的测试。

### 7.4 待验证的去重风险

network.py:345–363 使用两结构 free_bonds 并集，假定一侧测到 flat 就适用于另一侧。建议构建同 key、近能量但一侧 flat/另一侧不 flat 的算例检查误合并。本轮只确认实现及其假设，未复现实际误合并。事件自同构规范化也需复杂对称图反例测试，本轮不列为已证实缺陷。

**7.1、7.2 与失败落盘应进入首批正确性修复；随后再评估扰动与扫描策略的效率。**
