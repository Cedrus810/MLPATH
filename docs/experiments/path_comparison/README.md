# MLP 下降路径 vs QM IRC —— 到底差在哪

2026-09-04 · b04 SN2（Cl⁻ + CH₃Cl）· 复现：`python docs/experiments/path_comparison/compare.py`

两条路径：
- **MLP**：`runs/b04_probe2_openceiling/paths/ts0000/descent.extxyz`，
  PRRS 的 `descend_saddle` 在 **MACE-POLAR-1-M** 面上
- **QM IRC**：`docs/experiments/b04_qm/irc_IRC_Full_trj.xyz`，
  ORCA 的 IRC 在 **r2SCAN-3c** 面上

## 观察到的现象："在结果附近反复震荡"

```
MLP descent   58 帧   弧长 0.693 Å   每帧中位 0.0042 Å
QM IRC        23 帧   弧长 1.013 Å   每帧中位 0.0198 Å
```

**MLP 帧数是 IRC 的 2.5 倍，走过的路却只有 0.68 倍。** 分段看：

| 帧段 | 吃掉的弧长 | 每帧位移中位数 |
| --- | --- | --- |
| 1–10 | **48.1%** | 0.0305 Å |
| 10–20 | 27.3% | 0.0165 Å |
| 20–30 | 13.2% | 0.0033 Å |
| **30–40** | **1.5%** | **0.0010 Å** |
| 40–50 | 7.0% | 0.0045 Å |
| 50–57 | 2.9% | 0.0006 Å |

**前 20 帧走完 75%，后 38 帧（占三分之二）只走 25%。**

## 原因：那不是震荡，是优化器迭代被当成路径记了

`descend_saddle` 每一档做两件事：沿不稳定模走一步 `irc_step_A`，然后**淬火**。
`PathRecorder` 把 **FIRE 的每一次迭代**都记成一帧。所以后段那些帧不是路径进展，
是优化器在同一档里收敛。

能量证据：两侧都在**第 51 帧**最后一次变化（阈值 1e-4 eV），其后 6 帧是纯收敛尾巴
——几何在 0.001 Å 量级抖，能量四位小数不变。

**尾巴只占 10%**，真正的问题是中段（帧 20–50）：那里每档的淬火要迭代很多次才收敛，
而每次迭代都留了一帧。

## 第二个原因：MLP 路径两头都短

**首帧已经不是 TS。** `descend_saddle` 先走一整步 `irc_step_A` 再淬火，
所以记录的第一帧已经离开了鞍点（P3 的记录里量过：首帧比 TS 低 184.9 meV）。

b04 上：MLP 首帧 (2.109, 2.454)，而 TS 在 (2.281, 2.283)。**起点就下来了。**

### 这个差混了两件事，现在分不开

1. **势能面不同。** POLAR-1 的鞍点本来就比 QM 紧 0.083 Å（2.281 对 2.365），
   整条路径会跟着平移。
2. **路径构造不同。** IRC 是质量加权最陡下降；`descend_saddle` 是"走一步再淬火"，
   **每一档都往谷底压**，天然比真 IRC 紧。

**隔离实验**：用 ORCA 的 `ExtOpt` 在 **POLAR-1 面上**跑 IRC，再和 `descend_saddle` 比 ——
同一张面，只剩构造差异。桥接器已通（`scripts/mace_engrad.{py,sh}`，
单位契约验过：能量差 3.3e-11 Ha，梯度范数逐位相同）。
**未做**，风险是 ExtOpt 下 `Freq` 会撞 SHARK，IRC 的初始 Hessian 要改走
`InitHess read` 喂 PRRS 的解析 Hessian，或者数值化。
