## 2. 立项协议（冻结 · 先量后建）

1. **一条干预 = 一个名字 = 一次指纹位移 = 一次 digest。** 禁止两个 src 改动并步走
   （干预分别命名，教训已记两次）；P3 只许跟车：改某文件做别的修复时顺带修**该文件**
   的 P3，仍单独命名+单独变异检验。
2. 顺序：**测量 → 冻结改善判据 → 改码 → 验收。**
   - 基线测量协议逐干预写死（§2.1），用 cProfile/墙钟，复用既有 run 或合成重放；
     不新烧实验预算，除非落笔授权。
   - 基线数字出来**当场冻结**改善判据（形如「publish 墙钟占比降 ≥ 一半，且 digest 零
     差异」——阈值以实测为准，不预写）。
   - 验收 = digest 零差异（金样回归网，规模见 `docs/experiments/digest_baseline.json`）
     + 全部既有测试绿 + 新增回归测试**配变异检验**（把实现改回坏版本，测试必须红；
     绿本身不是证据）。
   - 指纹位移 → 旧 run 不能跨该次续跑（同 `REVIEW_2026-09-24` 修 5 的先例）；落地时机
     由落笔定（campaign 之间）。
3. fail-closed 照旧：优化不得引入降级路径；测量判不出差异就记 `unanswered` 并说明
   理由，不算成功也不算失败。

### 2.1 三个 P1 的测量协议草案

- **PERF-A**（=PERF-01）：对 exhaustive 规模合成 network（或既有最长 run 的
  attempts.jsonl 重放 publish），量 `publish()` 墙钟占比 vs attempts 数的曲线（预期
  二次性；`attempts.jsonl` 已是逐行记录，重放不碰 runs/）。
- **PERF-B**（=PERF-02）：对既有 b04 审计脚本做墙钟分解（能量循环 / membership /
  模型重载）；对照臂：calculator 提顶后同网格能量逐位一致。
- **PERF-C**（=PERF-03）：对 admit 密集 run（b05 类分子）量 chemical_key /
  torsion_profile / symmetric_rmsd 累计占比；对照臂：memoize 前后所有 key 与 canonical
  形式逐位一致（identity 不许动）。

## 3. 已排查干净（不再怀疑）

mace_server 模型只加载一次、无 per-request 重载；prrs_watch 对 observations.jsonl 的
tailing 确实是字节偏移增量（resize 只清缓冲不重读）；`network.py:543` 的 sidecar
np.load 只在 resume 时一次性；openmm 的 Context/Integrator 每 context 建一次并复用；
torch_guard 只在 `torch.load` 时走；主搜索的 `factory()` 是闭包复用同一 calculator；
`search.py:350-410` 的 resume 重建（含 attempts.jsonl 全量重写）是每次恢复一次的冷路径。
