## 1. 问题（实测）

两轮、三个体系，D2 的命中全部在预算末尾：v1.4 / v1.2 首次命中在 B* 的 85–95%，v1.5 在 87–94%（DONE_LOG 11-12、11-13）。原因是 `run` 严格分相：全部 L1 → 全部 L2 → GN → 全部 L3 释放 → HS / HC。HF-6 端到端的 R(b) 在 b ≤ 3/4 B* 时全为 0，这是 D2 在那次对比里最弱的一项。

## 2. 离线估算（只读，不调模型）

脚本 `benchmarks/explore_d2/f8_wave_replay.py` → `results/2026-11-14/f8_wave_replay.json`。v1.5 六个运行的每个任务保持它实际付出的 forward，只改付费顺序：L1 按运行自己的 L1 顺序切成 W 等份；每波 L1（及其 L2）之后立即付该波第一组（非第二轮、非同键图脊）的 HS + HC；GN 在第一个含成键改变脊的波次付；L3 释放、第二轮、同键图组在所有波次之后付。
核对：W = 1 且 L3 放在 HS 之前（即现行顺序）时，重排结果比实际首次命中早 2–8%（重排是串行记账，实际并行波次里同波其他任务也计入累计），可作为顺序效应的估计。

## 3. 规则（v1.6 = v1.5 + 下列调度变化；搜索判据、HS / HC 算法、额度与账户都不变）

1. **波次**：冻结的人口顺序（现行 `population` 排序，按姿态轮转）切成 W = 8 个连续等份。第 w 波：该波的 L1 → 该波的 L2 → 分类与升级 → 该波第一组的 HS / HC（并行波次，同 v1.4）。
2. **几何噪声（GN）**：在第一个含成键改变脊的波次测，取到该波为止的成键改变脊中按种子顺序的前 K = 4 个；测得后全运行使用。没有任何成键改变脊时，在最后一波之后用后备值（同 v1.5）。
3. **起点分簇**：增量计算——每个升级项与此前所有波次及本波已处理的组长比较，规则与半径同 v1.1；rank ≥ `first_round` 的项进入第二轮。
4. **留到所有波次之后的**（同 v1.5 的"在剩余额度上"）：L3 释放（搜索账户，放在最后，保证 L1 覆盖不被释放任务挤占）→ 第二轮 → 抽中的同键图脊 → 补跑组（G3）。
5. **续跑**：波次边界由冻结人口与已结算的 L1 决定，`run` 重复执行时按波次跳过已结算任务；kill → resume 不重付、不丢已结算几何。
6. 版本 `D2-HF-v1.6`，manifest 记 `waves`。v1.5 及更早运行行为不变。

## 4. 验证

1. 测试（`test_d2_hf.py`）：波次顺序（第 w 波的 HS 在第 w + 1 波的 L1 之前）；增量分簇与全局分簇在单波时相同；GN 在第一个含成键改变脊的波次；L3 在所有波次之后；外部计数 = 账本；在第 1 波 HS 中途、第 2 波 L1 中途 kill → resume。
2. 冒烟一次：b04 小规模（181）。
3. 整跑：三个体系 × 两个种子，L0 与额度同 v1.5，PBS 布局同 `v15_three_systems_pbs.zsh`；检验同 `v15_validate.py`（阶数 + 参照匹配，R(b) 网格），与 v1.5 并排比较首次命中成本与 R(b)。

## 5. 与现有设计的冲突（需要你定）

发现层设计 §4.2（用户 10-13 审定）："在其已选集合的 L1 基础试探覆盖完成后才开放 L2"，用意是"不让第一个来源吃完全部成本"。本计划在 L1 全部完成前就开始 HS / HC，字面上违背这一条。
本计划保留它的用意：L1 人口与顺序不变、按姿态轮转切波，每波都覆盖全部姿态；HS / HC 走独立的 refine 账户，不占搜索额度；L3 释放挪到所有波次之后，也不占 L1 的额度。所以 L1 的最终覆盖与 v1.5 相同，变的只是精修开始的时间。
是否以 HF 设计 F8（10-24）为准、把发现层 §4.2 这一条在 HF 线上标为"被 F8 取代"，由你定。
