# 分步与协同：这个套件要铺开的那条轴

用户 2026-09-04 定的框架。**这不是一张反应清单，是一条轴上的取样点。**

轴是：**一条通道上，反应物与产物之间有没有一个确认过的极小。**

- 有 ⇒ 分步
- 没有 ⇒ 协同

按 `README.md` 规矩 5，这个判断**只能是输出**。SN1 / SN2 / E1 / E2 这些名字是
人对过程的分步描述，不是势能面上的对象；把"应该有一个碳正离子中间体"写进前置，
等于把 PRRS 专门拒绝接受的那种输入从后门塞回去。

所以每一格的问法固定成一句：

> 搜索必须对"该通道上是否存在确认极小"给出答复。
> **两个答案都是 pass，答不出来才是 fail。**

这也是为什么这条轴值得做：**它是 PRRS 能回答而"给定机理算能量"那一类工作
按构造回答不了的问题。** ACS Catal. 2026, 16, 8053（见 `REFERENCES.md`）
把文献已提出的中间体和过渡态交给模型重新优化 —— 机理是输入。这里机理是输出。

## 取样点

排序按"打的轴"分组，不按化学教科书的章节。
状态与阻塞见 `MANIFEST.md`；这里只说每一格测什么、为什么不能被别的格子代替。

### A. 协同，单分子内（**已做完，三格同一条轴**）

| 体系 | 已有 | 备注 |
| --- | --- | --- |
| 丙二醛质子转移 | b01 | 退化，自环 |
| 3-氧代丁醛烯醇 | b02 | 不对称，A→B |
| 苯甲酰丙酮 | b03 | 芳香环 + 螯合 |

三者碎片数恒为 1，势垒 419/361/316 meV 同一带，虚频 −3186/−3010/−3086 cm⁻¹ 同一带。
**它们验证的是身份层与网络层的不同能力，不是不同的化学。** 这条轴已经饱和。

### B. 协同 vs 分步，同一底物上竞争（**离子化学，未开始**）

这是这条轴最经典的取样区，也是文献争议最多的地方 —— 正因为如此它适合做基准：
**"这个底物走分步还是协同"在真实化学里就是一个有答案但不平凡的问题。**

| 取样点 | 教科书标签 | 这一格实际问什么 |
| --- | --- | --- |
| Cl⁻ + CH₃Cl | SN2 | 取代通道上有无确认极小 |
| Cl⁻ + 叔丁基氯 | SN1 | 同上；标签预期不同，问法一字不变 |
| 仲碳底物 | "borderline" | 同上 —— **这一格最有价值，因为教科书自己说不清** |
| 卤代烷 + 碱 | E2 / E1 | 消除通道；与取代通道竞争，两条通道都要报 |
| 烯烃 + HX / X₂ | EA | 加成通道；溴鎓离子 vs 开放碳正离子是同一个问题的又一次出现 |

**取代与消除必须在同一格里同时报**，因为它们竞争同一个底物 ——
分开做会让"这个体系走哪条路"变成两次独立的单选题，而那不是化学里的问题形状。

### C. 协同，碎片数变化（**未开始，探针已绿**）

| 取样点 | 打的轴 |
| --- | --- |
| 环己烯 → 丁二烯 + 乙烯（逆 DA） | 碎片 1→2，重原子反应坐标 |
| 丁二烯 + 乙烯 → 环己烯（DA） | 碎片 2→1，协同 TS 的**同步性** |
| Cope / Claisen 重排 | [3,3] 迁移，碎片数不变但全是重原子 |

DA 的同步性是这一组独有的：一个 TS 上**两条键同时成**，而现有提案层一次只驱动
一个内坐标。这不是"能不能找到"的问题，是"找到的 TS 上两条键的进度是否相称"。

### D. 分步，多步循环（**金属催化，最远**）

论文（ACS Catal. 2026, 16, 8053）验证过 UMA 在这类体系上的能量与结构：
Ir 烷烃脱氢、Rh 氢甲酰化、Ru 烯烃复分解、Pd Buchwald–Hartwig、Cu 二氟卡宾。
MAE 对 ωB97M-V 是 2.8 / 1.9 / 1.7 / 1.7 kcal/mol 量级。

| 取样点 | 打的轴 |
| --- | --- |
| 氧化加成 / 还原消除 | 金属氧化态变化 |
| 迁移插入 | 配位数变化 |
| β-氢消除 | 与迁移插入互为逆过程 |
| 烯烃复分解经金属杂环丁烷 | **分步的教科书例**：[2+2] 然后逆 [2+2] |

**这一类现在做不了**，原因不在模型（POLAR-1 覆盖 83 元素、omol-0 覆盖 82）
而在 PRRS 自己，见下。

## 挡在这条轴前面的，是身份层不是模型

实测（2026-09-04，实现树 `23179deadf657452`）：

```
Cl⁻ 单独          →  stereo_unresolved = "no_assignment_satisfies_valences"
                     且 closed_shell_only=True 时域门 **拒绝** 它
Cl⁻ + CH₃Cl       →  同上。b04 的输入现在进不去
C≡N / Pd          →  stereo_unresolved = "unsupported_elements"，**不拒绝**
CH₃Cl 中性        →  None
```

```python
# src/prrs/chemistry.py
VALENCE = {1: 1, 6: 4, 8: 2, 9: 1, 17: 1, 35: 1, 53: 1}     # H C O F Cl Br I
```

三条后果，严重性递减：

1. **B 组被硬挡。** 阴离子不是"元素不支持"，是价键模型**写死了中性**
   （`# Neutral closed-shell valences`）。Cl⁻ 是完美的闭壳物种，只是带电。
   SN2 探针当时用 `closed_shell_only=False` 绕过 —— 那是把域门整个关掉，
   对基准不可接受：那样就没有任何东西在守训练域了。
   **正确的修法是让价键模型接受总电荷**，让 Cl⁻ 在 total_charge=−1 下价数为 0。

2. **N / P / S 缺席，砍掉 B 组一大半。** 胺作碱的 E2、SNAr、亲核酰基取代、
   膦配体、硫醇负离子 —— 全都出不了 `unresolved`。
   注释写明了这是**故意**的（"their valences are not single-valued in that setting"），
   所以扩表不是补一行数据，是一次要论证的设计。

3. **D 组（金属）不崩，但退化。** `unsupported_elements` 不被拒绝，
   key 退回图 + 碎片，立体化学记为 unresolved。这是有意设计
   （`network.py` 的 admit 注释）。**够不够用是个未测的问题** ——
   金属配合物的"图"由 `bond_scale × 共价半径` 判定，配位键在这个判据下
   算不算边，从来没有人验过。

**优先级推论：这三条修完之前，B 组和 D 组的判据都写不出来。**
不是因为难，是因为写出来的每一条都会立刻被域门拒掉，
而"被门拒了"和"没找到"按规矩 4 必须分开记 —— 那样的基准只会报出一列门拒绝。
