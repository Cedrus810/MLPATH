# benchmarks — PRRS 的反应基准套件

一格 = 一个反应体系 + 一组**跑前冻结**的判据 + 一个机械评定它的脚本。

叫 benchmarks 不叫 dataset，是因为在 run 存在之前这里**没有数据**。装的是**问题**：
结构、配置、判据、前置门。判据先于数据冻结是这个项目的核心纪律
（`docs/HANDOFF.md` §2），`dataset` 一词会把这个次序读反，而且这个项目满篇在讲
MLP 的**训练域**，那个词已经被占用了。

也不叫 examples：这些不是示范，是有 pass/fail 的门。示范那一格是 `runs/demo`。

评的是**方法**（PRRS 能不能不给产物就找到反应），不是模型。
`PRRS_ENGINEERING_PLAN.md` §7 里 P4 的交付物原话就是 "benchmark 报告"。

---

## 一格必须包含什么

```
bNN_<slug>/
  README.md        这一格打的是哪条轴；为什么它不能被已有的格子代替
  build.py         确定性地构建输入结构。不下载，不依赖网络，同一台机器可重跑
  config.json      SearchConfig 的完整 dict。冻结后逐字不改
  model.json       需要哪个 checkpoint、sha256、为什么是它、它的已知限制
  preflight.py     跑前必须绿的门 —— 见下
  preflight.md     preflight 的实测结果与日期
  CRITERIA.md      逐条判据、冻结时间戳、修订记录
  check.py         机械评定，逐条引用 CRITERIA.md 的原文
  reference.json   文献值，一律标注 literature_unverified_here
```

这个形状不是新发明。`docs/P2_OXOBUTANAL_ACCEPTANCE.md` + `docs/experiments/p2_check.py`
已经是它了 —— 这里只是把它固定下来，省得每一格重新长一遍，也省得下一个人
去猜 P1 和 P2 为什么长得不一样。

## 规矩

继承 `docs/HANDOFF.md` §2 的全部内容，另加四条属于这个套件的：

1. **preflight 先于判据，判据先于运行。**
   preflight 回答的是"判据能被写出来之前必须先知道的东西" —— 模型在这个化学上
   有没有意义、门会不会一律拒绝、要找的中间体在这个相里存不存在。
   `docs/P3_BENZOYLACETONE_PROBES.md` 是这类文档的范本：378 行，**没有一条是验收结果**。

2. **判据只写这一格声明负责的量。**
   `docs/HANDOFF.md` §5 已经划定：**PRRS 只负责 TS 在哪里、产物是什么。**
   势垒和虚频的绝对值是势能面的属性，不是搜索方法的属性。
   SN2 探针实测过这条边界的必要性：两个 charge-aware 模型在同一个反应上
   身份层逐字段一致，而过渡区的能量差 2.9 倍、最低本征值差 12.8 倍
   （`runs/sn2_probe.json`；换成波数是 √12.83 = 3.58 倍 —— **同一个事实的两种写法**，
   不是两条证据）。

   **为什么"好不好用"不能定义成势垒准不准，有一个干净的拆分：**

   ```
   A_θ[E_m]  vs  T[E_m]      ← 搜索方法好不好用（同一张 PES 上比）
   T[E_m]    vs  T[E_QM]     ← 模型准不准（交下游 QM）
   ```

   `A_θ[E_m]` 是 PRRS 在模型势能面上的输出，`T[E_m]` 是同一张势能面上
   独立求得的真值，`T[E_QM]` 是 QM 的真值。**把 `A_θ[E_m]` 直接和 QM 势垒比，
   会把搜索误差、旋钮误差、模型误差混成一个数，无法归因。**

   判据只能落在第一行，而且只落在身份与拓扑上；第二行不是这个套件的事。

3. **一格一条轴。** 加一格之前先回答：它测的东西，现有的格子哪一个测不了？
   答不上来就不加。P1/P2/P3 是同一类反应（分子内质子转移，碎片数恒为 1，
   势垒 419/361/316 meV 同一带，虚频 −3186/−3010/−3086 cm⁻¹ 同一带）——
   这个套件存在的理由之一就是让这种重复在加格之前就看得见。

4. **"没找到"和"被门拒了"必须分开记。**
   域门、collateral 门、closed-shell 门都会拒绝端点。一格的报告里，
   分母是**发起数**，被拒记被拒并附门的名字和理由，不记成失败。

5. **机理标签不得进入前提，只能作为结论。**

   SN1 / SN2 / E1 / E2 这些名字**不是反应，是人对过程的分步描述**。
   "SN1 有一个碳正离子中间体"是一句机理陈述，不是势能面上的事实；
   势能面上只有一个可测的问题：**那里有没有一个 `confirm_minimum` 通过的极小。**

   所以判据里**不许**出现"找到碳正离子中间体"这类条目。允许的写法是：

   > 该通道上是否存在确认极小，搜索必须给出答复；
   > 存在 ⇒ 记为分步，不存在 ⇒ 记为协同。**两者都是 pass，答不出来才是 fail。**

   这条不是洁癖。PRRS 的设计前提就是不预设反应坐标、不预设产物、不从 TS 猜起
   （`docs/HANDOFF.md` §1）。把一个人为的分步方案写进前置，等于把这个方法
   专门拒绝接受的那种输入从后门塞回去 —— 而且它会自我实现：
   给定一个"应该在那里"的中间体，扫描的幅度和方向都会围着它设计。
   `docs/HANDOFF.md` §2 那条"旋钮先验证再设计实验"说的是同一件事。

   直接后果：**SN1 与 SN2 不是两格，E1 与 E2 也不是。**
   它们是同一底物上"分步还是协同"这一个问题的两个标签，
   所以合成一格，把标签放在输出侧。

6. **本征值只在**已测量过**驻点性的几何上**才是频率。**

   ω² = λ/μ 要求驻点。**Hessian 是不是解析的与此无关** ——
   非驻点上的解析 Hessian 精确且无意义。`docs/HANDOFF.md` §4 的刚体地板
   量化的正是这件事：`ẋᵀHẋ = ω²(g·x⊥)`，**曲率正比于残余梯度**；
   那条对转动成立，对反应坐标同样成立。

   所以报一个 cm⁻¹ 之前，必须有**测量过的**梯度界，例如 `quench` 到 `fmax`
   之后 `confirm_minimum` 通过。**从对称性论证出来的驻点性不算** ——
   §2 的规矩是测量优先于推断，而对称性只保证非对称方向，
   对称子空间内的收敛还是要自己测。

   这条不是 §1 第 1 条的重复。那条管的是**有限幅度**响应不得称频率；
   这条管的是**幅度极限没问题、驻点前提没建立**的情形 —— 那是它的漏网形式，
   `runs/sn2_probe.json` 就是被它漏掉的一次。

## 状态词

`MANIFEST.md` 里每一格带一个状态，含义固定：

| 状态 | 意思 |
| --- | --- |
| `blocked` | 有明确的前置未完成。前置写在格子的 README 里 |
| `preflight` | 前置门在跑或已跑，判据尚未冻结 |
| `frozen` | 判据已冻结，可以开跑。冻结后 CRITERIA.md 逐字不改，改必须走修订记录 |
| `running` | 有 run 在跑；`runs/` 下的目录名记在格子里 |
| `done` | 有一次完整评定；结果和实现哈希都记下了 |
| `fixture` | **验收职责已移交，但结果仍有效**，保留为回归夹具。用于 P0–P3：它们的判据冻结过、判定通过过，只是验收这件事被 P4+ 的独立 QM 协议做得更好了。与 `retired` 不同 —— 它们不是被证伪，是被超越 |
| `retired` | 被更好的格子取代，保留不删（它的失败是方法记录） |
