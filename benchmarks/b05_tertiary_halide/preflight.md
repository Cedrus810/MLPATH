## gate 6（新合同版）：两条通道都有覆盖，缺口是"没被选中"而不是"基里没有"

**2026-09-09 按方向合同重写。** 旧版只用**被选中的**方向测覆盖，于是把两个理由混成一个。
新版分开测：完全枚举（`direction_mode="exhaustive"`）给出**基**能移动什么，
本格自己的模式给出这次**实际**能到达什么。

```
coordinate                in basis   this run   verdict
r_C_Cl_leaving                   5          2   covered
r_O_C_substitution              15          6   covered
r_C_H_beta                       5          0   candidate_not_selected     ← 不是基里没有
r_O_H_beta                      19          8   covered

channel verdicts        substitution: covered · elimination: covered
this run's mode         sampled   方向 24 / 候选 152
coverage_censored       True   by max_directions
full basis (exhaustive) 152 方向，censored False
```

**这纠正了本文件前一版的一句话。** 旧版写"`r_C_H_beta` 没有任何提案方向直接驱动它"，
听起来像基里没有 —— **不是**：基里有 **5 个**候选方向能移动那根 C–H，
只是方向预算一个都没选中。按裁决的词汇这是 `candidate_not_selected`，
**可修的那一种**（exhaustive 或更大预算就能覆盖），而不是 `basis_uncovered`
（那才是要改输入或改家族的永久缺口）。两个词分开，是因为修法不同。

**PASS 不等于负结论可采纳。** 它只说这一格能问出自己的问题。
"没找到"能不能采纳是另一个测试，按微态在该次运行自己的 `direction_ledger` 上做
（`CRITERIA.md` §5）。当前模式 `sampled` + `coverage_censored=True` ⇒
**这一格的每一条负结论都是 `unanswered`**。

## 2026-09-09：第一次探针**没跑起来**，卡在身份层而不是化学

`runs/b05_probe1_sampled` 在**第 1 个 trial** 就以 `IdentityUnavailable` 停下（`failure.json`
正常落盘）：

```
prrs: IdentityUnavailable: the automorphism group was not enumerated inside its budget,
so the bond delta is canonicalised against the identity permutation alone and the event
key depends on the limit rather than on the reaction.
```

**这是按设计的 fail-closed**（实现 `5d905aaa`：预算类失败不得成为身份），不是崩溃。

### 量出来的是枚举器的 scaling，不是旋钮设小了

```
                        |Aut|   枚举完?   耗时      orbits
b04 输入 (CH3Cl+Cl⁻)        6    是      0.8 ms    [3]
b05 取代产物              144    是     30.0 ms    [2, 2, 6]
b05 消除产物              288    是     54.4 ms    [2, 2, 2, 6]
b05 反应物 (tBuCl+OH⁻)   1296    否 ✗   —          [3, 9]
   limit 20 000 / 100 000 / 500 000 / 2 000 000  全部未枚举完
   limit 10 000 000                              枚举完，1296 个，**19.8 秒**
```

1296 = 3!（三个甲基互换）× 3!³（每个甲基的三个氢）。

**代价按最大轨道的阶乘走，不按群阶走**：轨道 3 / 6 / 9 → 0.8 ms / 30 ms / 19800 ms，
比值 37 与 660，对应 3!→6!→9! 的 120 与 504，同一量级。
**三个等价甲基的 9 氢轨道**是压垮它的东西 —— 枚举器没有用轨道稳定子或划分精化剪枝。

### 两条出路，代价不同，这是设计决定

| | 代价 |
| --- | --- |
| 把 `automorphism_limit` 提到 ~4×10⁶ | 键是对的，但**每个被接纳的结构 ~20 秒**（b04 那种规模一次运行 64+ 次调用）。而且 4×10⁶ 这个数没有实测依据，只是"够用"，正是 4a 禁止的那种反推 |
| 改进剪枝（轨道稳定子 / 划分精化，nauty 那一路） | 一次真正的代码干预，要单独命名与验收；改完 b05 与后面所有多甲基底物都受益 |

**换底物不是出路**：三个等价甲基就是叔碳这条轴本身。

**gate 9 现在把这件事挡在跑之前**（`preflight.py`）。它之所以是新加的，是因为
b05 的第一次探针**用一次失败的运行**发现了它 —— 那是最贵的学法。
先前那句"必需门 7/7"因此要读作"当时的门里少了这一道"。

### 1 逐条复现（在同一个松弛源微态上重新交付，纯几何）

```

             C0 位移 0.109–0.218 Å，撑断 C0–C6 / C0–C2 / C10–H12（0.057–0.133 Å，门 0.05）

             触门的是被驱动原子**自己**的键（C2–H5 等），0.065–0.446 Å
```

### 2 对照：保持非目标键长的几何交付

**bend —— 是交付实现缺陷。** 绕过顶点、垂直于 i–j–k 平面的轴把两侧片段各转 δ/2：

```
四例全部：达到同一幅度（误差 1e-16）· 非目标键变化 2e-16 Å · 现有门 PASSES
```

**pair —— 约束并不相容这个说法不成立，但需要的是复合驱动。**
固定键长键角、只转两个甲基（刚体），H···H 距离可达区间 `[1.89, 4.23] Å`：

```
15 个请求目标里 13 个够得着；(8,12)@1.0 与 (9,11)@0.6/1.0 够不着 —— 那三次拒绝保留
```

够得着的那些**只能靠驱动扭转去改一个距离**，即复合驱动。它现在有实测支持，
但**不在本次干预范围内**，也不能据此断言"复合驱动已被需要"。

## 两侧下降（用户裁决 2026-09-09 的第 ② 项）· `runs/b05_saddle_descent/`

`docs/experiments/b05_saddle_descent.py`。对续算得到的三个 order-1 驻点各做正负两侧局部下降，
沿用现有 `descend_saddle` + `confirm_minimum` 协议，六条轨迹与端点分别保存
（house 的 `PathRecorder`，`<trial>_side±1/descent.extxyz`）。

### 负模分解：是水的刚体转动，不是"局域在水上"这么笼统

质量加权约定写在脚本 docstring 里：`hessian_spectrum` 返回质量加权 Hessian 的本征向量，
笛卡尔位移是 `u_i = v_i/√m_i`；平动与转动子空间在质量加权坐标中构造（在那里彼此正交），
报出的份额是**质量加权模长平方**的占比 —— 与本征向量归一化的量一致。

```
                 水碎片占整条模    水内部：translation / rotation / internal
t000002            99.387%              0.1%  /  99.9%  /  0.0%
t000058            99.441%              0.0%  / 100.0%  /  0.0%
t000080            99.338%              0.1%  /  99.9%  /  0.0%
水的几何（三者相同）：r(O–H15) 0.9610 · r(O–H转移) 0.9717 · ∠H–O–H 103.45°
```

**H15 占 0.967 的疑问由此解决**：不是纯平动、也不是内部形变，是**绕水质心的转动** ——
氧近质心几乎不动，两个轻的氢在摆。先前只说"99.4% 在水上"确实不足以推出这一点。

### 六条下降：组成全部相同，只有水的取向不同；无一到达确认极小

```
路径              帧   ΔE vs 源(eV)  末帧 fmax   组成               ∠(O–H15, O→C0)  停止原因
t000002_side+1   580     -1.2916      0.0163   C4H8+Cl+H2O         99.5°   fmax_not_reached
t000002_side-1   107     -1.2790      0.0093   同                 108.0°   order 1, relays 4
t000058_side+1   107     -1.2796      0.0096   同                 107.4°   order 1, relays 4
t000058_side-1   589     -1.2909      0.0169   同                  99.4°   fmax_not_reached
t000080_side+1   111     -1.2785      0.0085   同                 108.3°   order 1, relays 4
t000080_side-1   587     -1.2923      0.0172   同                  99.0°   fmax_not_reached
```

两侧相差约 **9° 的水取向**，能量彼此在 13 meV 内，鞍点本身是 −1.277 eV。
**产物区是一片浅的水取向景观。**

**两种停止原因都是预算，不是物理终点：**

1. `fmax_not_reached`（三侧）—— 下降中的淬火用完 `quench_steps = 500`。
   **这是本次实验自己引入的混淆**：续算刚证明这个产物区差约 59 步，而这三条下降仍用冻结值 500。
2. `order 1, relays 4`（三侧）—— 淬火**收敛了**（fmax 0.0085–0.0096），
   落点仍是一阶鞍点，`irc_relay_hops = 3` 的中继上限（3+1 跳）用尽。
   中继机制正是为"若干鞍点彼此相距一步"建的，这里跳到上限仍是 order 1。

### 按判据记什么

- **不是** `observed_stepwise`：通道上没有确认的中间体极小。
- **不是** `observed_direct`：这个鞍点的模是产物侧的水转动，
  两侧到达的是同一产物集的两个取向 —— 它连接的是产物的两种排列，不是反应物到产物。
  实测证实了这一点（六条下降组成完全相同），而这**不能**当作反应物→产物的连接证据。
- 记为：**消除产物区域内的局部鞍点，其两侧连接未闭合（两道预算各挡三侧）**。

### 对 ③ 的范围结论：现在没有依据

裁决给 ③ 定的门槛是"先证明现有两侧下降无法妥善处理这类碎片软模"。
**这次没有证明它无法处理** —— 六条下降是被两道**从未放开过**的预算挡住的
（`quench_steps 500`、`irc_relay_hops 3`），其中一道还是本实验自己没跟上续算的 2 倍设置。
在增加新的打磨机制之前，便宜得多的检验是把这两道预算放开、重跑同样六条下降。
