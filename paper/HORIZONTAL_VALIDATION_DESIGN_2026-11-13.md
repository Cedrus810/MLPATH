# MLPATH 首篇横向验证设计

日期：2026-11-13。状态：**设计 v0.1；未实施、未启动模型/QM 计算，未冻结正式运行。**

依据：[论文初稿](MLPATH_MainText.md)、[SI](MLPATH_SI.md)、[HF-5 小结](../docs/HF5_SUMMARY_2026-11-10.md)、[HF-6 小结](../docs/HF6_SUMMARY_2026-11-12.md)、[10-13 评估协议](../docs/EVALUATION_PROTOCOL_DESIGN_2026-10-13.md)及[通用规则选项](../docs/HF_GENERAL_RULES_OPTIONS_2026-11-12.md)。旧协议、运行和初稿数据保持原状。本设计提出首篇 HF 搜索的执行范围，不自动增加旧协议中的 D0/D1、PARS 或动力学比较。

## 1. 要回答的三个问题

1. **局部定位能否迁移？** 规则固定后，在不同反应物和反应坐标条件下，扫描产生的括区能否被 E/F 定位器经济地精修成独立确认的 TS？
2. **完整寻找是否划算？** 将姿态、校准、扫描、失败、TS 搜索及认证计入双方实际成本，从共同反应物输入出发，D2 与 Dimer 各自能发现哪些连接？
3. **优势和漏检来自哪里？** 区分局部优化收益、初猜覆盖、筛选漏失、模型参照资格和数值未决，保留 N1 协同 DA 与 b05 新取代通道两个已有反例。

首篇主张限定为上述任务和入选体系。跨模型泛化、全反应空间完备性、PARS 选择收益、committor、分岔比例及溶液动力学各自另行验证。横向一期不为它们增加计算。

## 3. 留出选取：按反应物分组，选择与搜索结果隔离

### 3.1. 数据来源与获取边界

主来源选 **RGD1 的 2023-04-24 更新记录**，以保留旧协议 N3 的单反应物多通道问题。作者数据记录包含映射 SMILES、几何及能量，并指出初版约 24% 的正反向活化能曾颠倒，更新版已更正：[数据记录](https://zenodo.org/records/7860446)、[数据论文](https://doi.org/10.1038/s41597-023-02043-z)。此版本信息在本次设计时已核对。

Transition1x 作为记录可获取性不足时的备选来源。它提供反应物、路径及 TS 区域的 DFT 数据，适合列候选；路径峰仍须在本研究目标 PES 上重新认证：[原始数据论文](https://doi.org/10.1038/s41597-022-01870-w)。其数据库规模和源计算不构成本模型的参照资格。

本次只核对公开来源，没有下载数据集。后续先处理索引与选中记录，避免下载原始输出全集。RGD1 所选 Zenodo 记录的索引 CSV 约 60.7 MB、反应 HDF5 约 1.3 GB，原始输出约 28.7 GB；确需完整几何容器时只获取该容器一次，不重复下载原始输出包。

留出针对**搜索规则和本项目调参**。本地 checkpoint 的训练数据重叠尚未审计，因此本设计不称这些分子为模型训练分布外测试。

### 3.2. 不看算法表现的入选程序

按以下顺序执行并保存每一步计数：

1. 固定源记录版本、索引字段、原子映射规则；合并同一反应物的构象、反向记录与重复条目。分组使用反应物化学身份，构象另列。排除已参与本项目规则开发的反应物身份。
2. 首批只取 C/H/O、总电荷 0、multiplicity 1、非周期、单个连通反应物，重原子数 3–10、总原子数 ≤25。源记录缺电荷/多重度信息时记 `state_unverified`；不能只因只含 CHO 就推定闭壳层。原子映射、来源几何缺失记 `source_incomplete`。
3. 参考端以映射后的反应物/产物图差作分层：H1 至少一个 H 改变重原子连接；H2 至少一个重原子—重原子连接变化且无 H 改变连接；H3 同一反应物至少两个不同映射事件。同一分子只能占一个槽位，按 H3→H2→H1 顺序分配。图差只是选层标签，不提前断言协同/分步机理。
4. 每槽按 `(重原子数, 总原子数, 源反应物稳定 ID, 源反应记录 ID)` 升序排序，预先登记前三个不同反应物及其替补顺序。每个单事件槽取排序最前的两份可用 TS 记录；H3 取前两个不同事件，每事件至多两份 TS 初猜。保留相应来源信息，不声称这些记录穷尽该分子的通道。
5. 独立参照端按 §5 在目标 PES 上认证，禁止运行 D2/DB 发现来决定是否合格。每槽按已登记顺序最多检查三个反应物；H1/H2 至少一条目标 PES C2，H3 至少两条不同事件的 C2，才有该槽的预定参照资格。
6. 三个反应物均无资格时，槽位记 `reference_axis_unavailable`。保留所有失败和支出；该轴不出方法优劣结论，不自动再找十个直到挑到成功体系。来源记录不可获取时可按预登记备选源重复同一索引筛选，但仍共用每槽三个参照候选的总上限。

顺序按规模优先会偏向小分子，论文明确披露这一范围限制。目标 PES 参照资格筛选也会选择模型可表示的部分，需报告资格通过率及排除原因。

### 3.3. 搜索端能看到什么

搜索端只能读取反应物原子/坐标、电子态、通用模型与方法配置。H1/H2/H3 的图差分层、参考产物、TS、负模、缺失参照名单均留在评分端。不得利用“这是 H 转移槽位”改变意图优先级，也不得按 H3 的两个已知事件设计组合坐标。

任一留出结果用于修改算法后，该反应物转为开发集，其确认资格终止；历史结果保留。需要新的真正留出时另登记版本，不在同一确认表里静默替换。

## 4. 开发阶段只冻结一套方法

### 4.1. 提议的统一 profile

下表是本设计的施工建议，**不追认 11-12 选项已经获采纳，也不代表源码已具备该行为**。统一 profile 暂记 `HP-1`；实施版本号待实际接线和验证后登记。

| 项 | HP-1 设计建议 | 本轮必须先解决的点 |
| --- | --- | --- |
| E/F locator | 统一当前 v7 的候选规则；搜索保持 E/F，BFGS secant/FIRE 的范围固定 | b04/b05/N1 当前 cohort 设置不同，需同一 profile 接线 |
| 同键图脊 | 采用 G3：比较扫描起点与峰后有效低点，抽查出连接后将余项重新排队 | 与旧 G3 一致，以臂内 HC 结局触发；不得以“匹配哪个参照”触发；重排不增加预算，可能仍来不及执行 |
| 反力 σ 与粗阶段 B | 开发校准起值 σ=0.0042、B=0.025 eV/Å，作为同一 checkpoint/精度的统一候选常数 | 未经校准不称已定数值；校准失败统一修订，禁止逐体系加例外 |
| 几何噪声 | 固定运行内测量程序，费用进入 D2：按稳定随机顺序取至多四个有效脊，每点八次 0.01 Å 扰动后同 q 松弛 | 同支几何判据沿用已记录 0.05 Å；换盆重复单列，不混入噪声 |
| 没有可测脊/同支样本 | 记 `calibration_unavailable`，本期停止该块的 D2 后续搜索并保留费用 | 不填零、不借参考 TS 测；DB 继续其自身预算。该块进入端到端失败统计 |
| 能量分辨率 | 候选取 `2 × spacing(float32(abs(E0)))`，E0 来自该块通用准备后的第一份有效输入 | 两个量子的依据有限，开发实测不过则统一修订；不同构象盆能差不能当噪声 |
| 意图 | 本期仍用通用单距离原语；扫描幅度、远层取样和配额一次冻结 | 不为 N1/H1/H2/H3 加答案专用坐标；二元意图另作后续版本问题 |
| 调度 | 本期保持阶段顺序，避免同时改筛选、locator 和交替调度 | 正式报告首次命中晚的问题，不预报改调度能解决 |

几何测量使用已收敛约束帧，同 q 重松弛阈值 0.001 eV/Å，位置最大原子步长及单次松弛上限沿用冻结的 locator 设置。先剔除同 q 终点 RMSD 超过 0.05 Å 的重复，再以剩余同支终点相对其组 medoid 的 RMSD 最大值作为点估计，点间取最大。每点至少四个同支终点才可估计；不足则该点未决。最多四点全部不可用，按表中的不可测规则处理。这些是待开发校准的固定程序选择，不是已有实测结论。

此保守不可测政策会降低 D2 完成率，是本期显式代价。若开发校准显示它使 b04 等简单体系停线，先在开发集修订一个通用后备规则，再冻结 HP-1；不能留到留出结果出来以后补参数。

### 4.2. Dimer 数值适用性，先于比较冻结

在三个开发体系各取两个预登记帧：一个历史收敛点和一个已记录难例，共六帧。比较分离距离 `10⁻⁴ / 10⁻³ / 10⁻² Å`，每个配置冷启动重复两次。HF 同六帧重复作数值对照；单次搜索上限仍为 3,000 forward。最大搜索费用为 `6 × 4 × 2 × 3,000 = 144,000`，与额外力/验证校准共用 §9 的上限。

为三种分离距离分别记录：同帧力噪声与方向差分量、曲率符号、模式重现、数值异常、最终无偏全力、驻点几何及一阶分类。固定诊断方向取该帧 intent 梯度，测 `d = n·[F(x+εn)−F(x−εn)]`；每个固定坐标重复八次，不施加几何扰动。只有两次冷启动诊断均有限、符号一致且 `|mean(d)| > 3 sd(d)` 的帧才计为该配置的数值可分辨帧。八次样本和 3 倍系数是开发校准政策，不能据此给总体概率保证。

**先按数值可分辨性排除六帧均不可分辨的配置**；其余配置按 `(可分辨帧数降序, 求值/线搜索数值异常数升序, 重复间曲率相对差中位数升序, ε升序)` 唯一排序。无可比较曲率的帧保留未决，不填零参与相对差。不得用某个体系参照命中最多来为该体系挑配置。若三者都无法建立可用数值尺度，先修共同精度/实现再比较，不以一个失效默认配置支撑优势。

校准结果、选择理由与被排除配置全部入 SI。正式阶段只保留一个 Dimer 配置，各体系照用。历史默认 ASE Dimer 结果仍单列，不事后替换其参数。

## 5. 共同认证：驻点性质与 C2 连接分开

### 5.1. 参考集合 S 的资格

评分端可以使用源 TS/两端信息，在目标 checkpoint 上重优化并认证。TS 满足无偏完整力 ≤0.01 eV/Å、一阶内部负模；两侧有下降证据并到达完整力 ≤0.01 eV/Å、无显著内部负模的端点。保留 charge/spin/原子映射、位移、两侧轨迹、几何及预算。

固定参照集合只含正式搜索前已完成上述证据的条目；最终参考几何还需在 fp32 和 fp64 两种求值下均满足同一全力门，以标明搜索与数值认证的共同驻点资格，未通过记 `precision_stationarity_unresolved`。b05 要对已发现的取代候选补端点极小核验；通过则与已知 E2 一起登记到新版本 S，否则记资格未决，不能写“取代通道也已纳入答案”。N1 的四个参照同样核查端点和微态资格。几何初猜使用文献许可，但搜索端不读它。

### 5.2. 验证器 V1 的提议

本期搜索维持 fp32，**搜索后认证统一使用同一 checkpoint 的 fp64 求值**，单独记录这是数值验证配置。先在原始候选几何上评估 fp64 全力；超过同一力门则记 `validation_force_unresolved`。若未预登记共同 polishing 策略，就不在评分端悄悄优化一个新鞍点再回填成功。

V1 提议使用 0.01/0.02 Å 两步长中心差分内部 Hessian，沿用现有 10⁻³ 特征值判阶配置，显式保存其单位和刚体投影实现。两步长的内部阶数/刚体一致性检查均通过才给性质判定；不一致记 `order_unresolved`。负模重叠与临界特征值连续报告，不增加一个为本批结果选择的重叠阈值。不得关闭内部模复核使它通过。

两侧下降从 ±负模开始，初始最大原子位移沿用 0.15 Å，端点仍独立验极小。验证器只在开发集校准，六个体系共用；若 fp64 本地 calculator 不支持该 checkpoint，停止 V1 开工并先解决接口，不混用别的模型 Hessian。共用阈值和差分步长是待校准配置，源码/运行通过后才标 V1 可用。

所有 fp64 能量匹配只与 fp64 参照能量比较。fp32 残差和 fp64 残差并列；不混精度相减。主文分别报告 `stationary_candidate`、`index_one`、`C2` 与 `QM_status`。

### 5.3. 身份、对称与参考外发现

沿用已记录的 0.15 Å 几何与 0.05 eV 能量匹配尺度，开发阶段复核其区分能力，正式期锁定。元素、电荷、映射、事件与端点微态同时检查；同端点不自动合并 TS。

镜像规则按反应物/任务定义预登记。无手性输入且评分明确对映等价时可商镜像；有指定手性时保留区别。不得无条件对所有体系取镜像最小 RMSD，也不再把鞍点自身图群当作全部允许置换。

独立新 C2 进入“参照外发现”表，**不修改本轮 S 的分母**。下一版本可吸收这些发现，但要注明已经看过的批次。未完成端点验证的项单列，不计为新 C2。b05 的现有额外取代结果按其当前证据等级保留。

## 6. 第一层：六体系的局部横向比较

### 6.1. 输入库及未形成括区的情况

每体系两个独立反应物构象/姿态块，每块按固定随机流选十二个通用意图。输入的构象生成只能读反应物。每意图最多 800 forward 扫描、200 forward 反扫；固定截断后停止，不因没有参照方向而追加意图。

每块的输入库总 cap 为 25,000 forward，其中最多 13,000 用于 L0 准备和 HP-1 的固定校准，最多 12,000 用于十二项扫描/反扫；准备或校准先用尽时保留未执行意图，不借用未发生的费用填账。D2 专用校准在生成费用里具名单列，不称为 Dimer 的必要准备。

共同冻结每个扫描的完整状态、峰点、括区两端、方向与费用。凡能按冻结规则形成有效 HS 输入者同时交给 HF/Dimer；不能形成者记 `no_valid_bracket`，保留在输入库覆盖分母，不用后续成功意图替换。因此每体系**最多**二十四个有效局部任务，实际可能更少。

HF 收两端括区；Dimer 收该括区内峰点和同一 intent 梯度方向。这是同一来源信息下的算法接口比较，保留两端信息与单点初始化的差异。它条件于 D2 生成的输入库，不能独立证明不依赖该生成器的通用优化器优势。

### 6.2. 两层成本与输出

每个有效输入的每臂搜索 cap 3,000 forward；候选后的共同 V1/C2 认证 cap 3,000 forward。分别给出：

- 固定有效输入集合上的局部搜索费用、全力残差、候选数、V1 一阶通过率、失败与未决类型。
- 在搜索＋认证 cap 内闭合的 C2 成功率、首次完整 C2 费用及不同鞍点身份。
- 输入库生成的意图数、有效扫描数、有效括区比例和费用。没有有效括区的体系，条件局部成功率为 NA，而输入覆盖为零。

两臂的后置认证受同样预算控制，失败同样付费。局部“一阶”表可以列搜索费与认证费两栏；“完整 C2”表将两者相加。重复候选不当成新通道。

### 6.3. 两个最小消融的安排

一期只执行 **A1 warm/cold**：三个开发体系各固定六个有效括区，在完整 HF 之外增加关闭曲率复用和切向预测的 cold 臂，其余设置及候选门不变。十八项，每项搜索＋认证最多 6,000 forward。它回答复用策略的合并收益；不把这一个合并消融归因到其中某个单独技巧。

**A2 筛选开/关**保留为第二优先级：若要将 G3 的节约作为主文贡献，需要在 b05/N1 的共同 L0、同总费用下完整比较，包含被筛项抽查、认证与失败。离线重放只能描述候选排队集合，不能替代这个因果对照。一期先不增加整跑消融；因此一期文章不将 G3 的独立贡献写成已确认结论。

## 7. 第二层：四体系的端到端比较

### 7.1. 固定臂和块

体系：b05、N1、H2、H3。两臂：统一 HP-1 的 D2 与数值校准后的 ASE Dimer。每体系四个配对块，块由独立反应物构象/姿态采样和搜索随机流组成；双方同块共享 L0，其余随机流按 arm/stage 分开。独立来源不足时按真实层级报告，不把四次同坐标复算称为四个独立来源。

每臂每块的有效总预算先提议为 **500,000 forward**，包括共同准备份额与臂内完整 C2 认证。该数略高于现有 b05/N1 开发 ledger 的约 0.38–0.41M，并为统一认证留空间；它是一期资源上限，不是已测得足够的预算。四体系使用同一上限，避免按谁快找到答案反向设预算。

首波只排每体系第一个配对块，资源上界 4M forward。确认同一冻结配置、完整账本与工件正常后，执行其余三个块；**首波属于本期四块，不是用来调算法的 pilot**。是否存在正面收益不改变四块的预定样本量。若首波暴露实现错误，整批标失效/开发，修订版本后重新预登记，保留原支出。

四块是有界描述性重复，不提供已校准的显著性功效。本期不宣称总体统计优势；若需要确认效应大小，先用独立开发数据确定最小实际收益和样本量，再开新的确认批，不依据留出结果边看边加 seed。

### 7.2. 共同比较的完成点

对每块，令共同准备支出为 P，臂内累计支出为 A。每臂比较曲线坐标使用 `P+A`。共享 P 实际只执行一次，但每臂有效成本均加 P；项目实际总支出按 `P+ΣA+参考准备+额外QM` 报告，不把共享执行次数重复相加。

臂内 A 必须包括自动校准、探针/扫描、失败、TS 搜索、候选去重所需新求值、V1、两侧下降和端点验证。D2 已做过的、满足共同合同的 HC 工件可直接进入共同验证，不重复收费；未满足者补足并记新增费用。DB 候选接受同样的 C2 合同，不再把其端点认证全挪到预算外。

第 i 条参照的首次成本为**该臂 C2 证据全部闭合时的累计 P+A**。预算外补验只能用于诊断，不回填到预算内。候选于 100k 出现、到 120k 才通过 C2，其曲线台阶在 120k。

### 7.3. 预算分配

每臂在扣除 P 后，初始将可用 A 的 80% 分给搜索、20% 保留给共同认证；该比例是资源策略提议，开发预估不够时统一修订，正式期不改。每项初始 TS 搜索 cap 3,000，单候选 C2 cap 3,000，所有失败和重试进入同一总账。

认证按臂内候选出现顺序轮转，便宜的几何重复先处理；不看参照身份排序。搜索子额度结束后，先处理已产生候选。队列清空且仍有余额时，将剩余额用于新的“搜索＋最多一次认证”完整任务包；余额不足预留完整包时停止，不用掉认证保留额只堆未核验候选。

若 P 已超过有效总预算，记 `preparation_budget_exhausted`，两臂该块都无搜索；P 的预处理本身同样受上限控制。若某臂仅因自身校准或扫描花尽额度，其 C2 召回按零/已闭合项报告，不能删掉这个块。

### 7.4. 指标

主指标：预算内独立 C2 参照召回 `R_C2(B)`，及各参照的首次完整 C2 成本。参考外 C2、唯一化学事件、同连接不同鞍点、重复与未决分别列。

在 `0, 1/8, 1/4, 1/2, 3/4, 1` 的预算比例及全部真实命中点给曲线；辅助给归一化 AUC。未命中为右删失，不填一个伪造的命中成本 B；所有臂全零时报告该预算下零召回，成本比值和胜率中不做除零。

按体系给四个配对块原值和 D2−DB 差值；局部结果可将三个留出分子等权汇总，端到端留出均值只对 H2/H3 等权，开发体系另表。H1 未做端到端不填零。姿态/意图/参考数不当作独立分子样本。小样本不配一个看似精确的 pooled CI，也不因差异不显著写等效。

所有被称为 C2 的结果均进入共同检查；检查未决与独立复核明确失败分开。候选数、HS 成功率、GPU 利用率及局部 forward 节省均为辅助指标。

## 8. 正式前冻结清单与来源记录

只有以下记录齐全后，才能标“正式可运行”；本设计当前不填已经完成：

| 记录 | 最少字段/内容 |
| --- | --- |
| `systems` | 角色、真实源记录 ID/版本、反应物身份、元素/电荷/多重度、资格及排除原因 |
| `references` | 独立 saddle ID、源/目标 PES、原子映射、驻点/端点/两侧工件、V1 和 QM 状态 |
| `protocol` | HP-1、Dimer、V1 的全部有效参数与校准结果、镜像政策、局部/端到端成本合同 |
| `inputs` | 各块 L0、意图和随机流表；搜索端与评分端目录隔离 |
| `execution` | 实际源码提交/修改状态、checkpoint 版本、calculator 有效行为、环境、精度、设备与真实 hostId |
| `budget` | P/A/参考/QM 账户，上限、预留和回收政策、首次闭合时间、重试/恢复支出 |

不增设一个靠新哈希绕过实际来源核验的机制。已有工作区有未提交内容时，在可操作的实际 Git 主机上固定完整实现；未绑定来源的批次保留为开发证据。阶段版本、候选/块 ID 与执行 attempt ID 分开，NFS 写入端读取状态，原失败工件不覆盖。

## 9. 资源边界：先局部，再端到端

以下全部是 **forward 硬上界提议，不是预报实际消耗，也不是已授权启动的作业清单**。本次消耗为零。高阶自动微分、fp64 相对耗时、CPU 后处理、峰值显存和墙钟另记，不能用同一 forward 数声称同时间。

| 阶段 | 规模/计法 | forward 上界 |
| --- | --- | ---: |
| 开发数值与验证器校准 | 六帧、多分离距离、重复、V1 及旧三体系参照补验（含 b05 取代候选），共用封顶 | 250,000 |
| 新参照资格 | 三槽 × 最多三个反应物 × 每反应物 30,000；多个 TS 共用这个 cap | 270,000 |
| 局部输入库与准备/校准 | 六体系 × 两块 × 25,000；每块含十二意图扫描/反扫最多 12,000 | 300,000 |
| 局部搜索＋共同 C2 | 最多 144 括区 × 两臂 × (3,000+3,000) | 1,728,000 |
| A1 cold 增量 | 十八个开发括区 × (3,000+3,000) | 108,000 |
| **到局部横向结束的累计上界** | 上述五项之和 | **2,656,000** |
| 端到端首波 | 四体系 × 一块 × 两臂 × 500,000 | 4,000,000 |
| **含首波累计上界** | 2.656M + 4M | **6,656,000** |
| 端到端全四块 | 四体系 × 四块 × 两臂 × 500,000，已含首波 | 16,000,000 |
| **一期全部累计上界** | 2.656M + 16M | **18,656,000** |

表中端到端把每臂的共同准备份额也算入上限，因此是保守有效成本总和；共享 P 只执行一次时项目实际求值可更少。局部没有形成有效括区时相关搜索/验证费用也少于上界。参考资格不足的槽位不强行填满支出。

本期不排新 QM 批、不排 A2 整跑、不排第二模型。需要这些工作时按已获得证据另定边界。墙钟/节点数尚未测定；正式作业表应根据实际选中结构、fp64 V1 开销与可用设备换算，不能把历史三进程共卡的耗时直接当独占 GPU 速率。

资源不足时，完整四块端到端仍为未完成计划；可交付六体系局部＋已执行首波的描述性结果并明确范围，不以“验证通过”结束，也不挑胜出的体系省略其余。

## 10. 停止与异常处理

| 情形 | 固定处理 |
| --- | --- |
| 源/目标模型参照资格未通过 | 记录资格失败和费用；按三候选上限推进预登记替补；全失败则该轴 unavailable |
| 搜索端没有括区或没有候选 | 覆盖失败/预算截断，保留零产出；不追加成功输入替代 |
| 所有留出均低覆盖/全零 | 如实完成既定表；收窄文章主张，不逐体系改阈值救结果 |
| 阶数/端点未决 | UNKNOWN；不计 C2，保留几何及未决原因 |
| 参考集合为空 | 参考召回 NA；该轴有额外发现也不填 100% |
| 数值校准不通过 | 在开发阶段统一修订；正式期发生则该块记数值失败，禁止按反应特调 |
| 发现实现/账本错误 | 停止依赖该错误的批次，保留原始结果和已付成本；修复后新版本，不补写旧运行身份 |
| 外部中断 | 恢复不回滚已付成本；无法恢复的 attempt 保留，同 seed 按预定政策重做一次，追加成本仍受总 cap 控制；不能择优挑结果 |
| 留出暴露后提出新规则 | 转为开发，另开确认版本；旧表保留其原角色及暴露时间 |

阶段之间不以“看起来快赢了/快输了”改变正式块数。资源停止与正确性停止各自具名，已发起块全部纳入工件表。

## 11. 论文怎样接收这些内容

正文保留四组核心结果：局部横向图、完整 C2 预算—召回、反应事件覆盖与额外发现、N1/失败边界。开发与留出分别标记；图中分母、未决和未执行格可直接读出。

Methods 讲清约束分支、反力括区、全力候选门和共同认证。版本沿革、六体系参数、数值校准、全部失败、身份/镜像细节与环境放 SI。A1 若有结果再写；G3 独立收益、交替调度收益、跨模型泛化在相应实验完成前不进入结论。

现有 `paper/data/` 和两图继续代表 HF-6 开发数据；正式横向结果放新目录和新注册表，不用新认证结果覆盖旧评分。第一版主文的开发曲线与新 `R_C2` 必须使用不同名称和图注，不能接成一条连续曲线。
